# База данных: инфоблоки, свойства, контент

Документ описывает слой данных, который создают миграции `db/`. Это источник
правды для шаблонов компонентов: коды инфоблоков, коды свойств и XML_ID
значений списков должны совпадать с тем, что написано здесь.

Установка и запуск миграций — `../db/README.md`. Здесь — модель данных.

---

## 1. Зачем отдельный слой

Шаблон `nlb_bootstrap` — оформление. Данные приходят из инфоблоков Битрикса:

```
db/config/iblocks.php      структура: типы, инфоблоки, свойства, разделы
db/config/data/*.php       демо-контент: элементы с датами и свойствами
db/migrations/*.php        создание структуры через API Битрикса
        │
        ▼
   MySQL (b_iblock*, b_iblock_element*)
        │
        ▼
bitrix:news.list / news.detail  → шаблоны news_cards, events_cards, article
```

Коды, а не ID: на каждой установке ID свои, коды одинаковые. Поэтому в
вызовах компонентов используется `IBLOCK_ID` из поиска по `CODE`
(см. § 7), а не число из демо-базы.

---

## 2. Типы инфоблоков

| ID | Название | Разделы | Для чего |
|---|---|---|---|
| `nlb_content` | Контент библиотеки | да | новости, события, коллекции |
| `nlb_catalog` | Каталог книг | да | книги |
| `nlb_services` | Услуги библиотеки | нет | услуги и печать |

Свои типы, а не демо-тип `news`: при обновлении демо-данных Битрикса
(`/bitrix/modules/*/install`) чужие типы не затрагиваются, а свои — тем более.

---

## 3. Инфоблоки

| Код | Название | Тип | Список | Детальная | Раздел |
|---|---|---|---|---|---|
| `news` | Новости | `nlb_content` | `/news/` | `/news/#ELEMENT_CODE#/` | `/news/#SECTION_CODE#/` |
| `events` | События | `nlb_content` | `/events/` | `/events/#ELEMENT_CODE#/` | `/events/#SECTION_CODE#/` |
| `collections` | Коллекции | `nlb_content` | `/collections/` | `/collections/#ELEMENT_CODE#/` | — |
| `books` | Каталог книг | `nlb_catalog` | `/books/` | `/books/#ELEMENT_CODE#/` | `/books/#SECTION_CODE#/` |
| `services` | Услуги | `nlb_services` | `/services/` | `/services/#ELEMENT_CODE#/` | — |
| `printing` | Печатные услуги | `nlb_services` | `/printing/` | `/printing/#ELEMENT_CODE#/` | — |

Общие настройки всех инфоблоков:

- `ACTIVE = Y`, `VERSION = 2` (свойства в отдельной таблице);
- права: группа 2 «Все пользователи» — `R` (чтение), иначе гости увидят пусто;
- `INDEX_ELEMENT = Y` — элементы участвуют в поиске;
- символьный код обязателен, транслитерация включена.

## 4. Свойства

### 4.1. Новости (`news`)

| Код | Название | Тип | Множ. | Примечание |
|---|---|---|---|---|
| `AUTHOR` | Автор | строка | нет | подпись карточки |
| `TAGS` | Теги | список | да | фильтр и бейджи |
| `READ_TIME` | Время чтения | строка | нет | «4 мин» |
| `SOURCE_URL` | Источник, ссылка | строка | нет | внешний материал |

### 4.2. События (`events`)

| Код | Название | Тип | Примечание |
|---|---|---|---|
| `DATE` | Дата и время | строка + `DateTime` | хранится в формате сайта |
| `PLACE` | Место проведения | строка | зал/этаж |
| `CATEGORY` | Категория | список | задаёт цвет бейджа |
| `FORMAT` | Формат | список | офлайн/онлайн/гибрид |
| `SEATS` | Мест | число | ограничение записи |
| `PRICE` | Стоимость | строка | «Бесплатно» |
| `DURATION` | Длительность | строка | «1,5 часа» |
| `REGISTER_URL` | Ссылка на регистрацию | строка | ведёт на форму |

> **Важно.** `DATE_ACTIVE_FROM` у события — дата **публикации**, а не дата
> мероприятия. Иначе `CHECK_DATES => Y` скрыл бы будущие события из афиши.

### 4.3. Каталог книг (`books`)

| Код | Название | Тип | Примечание |
|---|---|---|---|
| `AUTHOR` | Автор | строка | поиск по автору |
| `YEAR` | Год издания | число | сортировка |
| `ISBN` | ISBN | строка | демо-значения |
| `PUBLISHER` | Издательство | строка | |
| `PAGES` | Страниц | число | |
| `AGE_LIMIT` | Возрастное ограничение | список | `0plus`…`18plus` |
| `AVAILABLE` | Доступность | список | `available`/`reserved`/`unavailable` |
| `SHELF` | Шифр / полка | строка | «84(2Рос)6 / Ш-78» |

Обложек в демо-наборе нет: карточка книги рисует цветную заглушку, пока
контент-менеджер не загрузит детальную картинку.

### 4.4. Коллекции (`collections`)

| Код | Название | Тип | Примечание |
|---|---|---|---|
| `COUNT` | Книг в подборке | число | бейдж |
| `COLOR` | Цвет карточки | список | `primary`…`orange` |
| `ICON` | Иконка | строка | код символа спрайта без `i-` |

### 4.5. Услуги (`services`)

| Код | Название | Тип | Примечание |
|---|---|---|---|
| `ICON` | Иконка | строка | `book`, `laptop`, `users`… |
| `COLOR` | Цвет | список | `primary`…`orange` |
| `PRICE_FROM` | Цена от, ₽ | число | `0` = бесплатно |
| `DURATION` | Режим / длительность | строка | «Пн–Сб, 10:00–21:00» |

### 4.6. Печатные услуги (`printing`)

| Код | Название | Тип | Примечание |
|---|---|---|---|
| `ICON` | Иконка | строка | `file`, `scan`, `card`… |
| `COLOR` | Цвет | список | |
| `PRICE_FROM` | Цена от, ₽ | число | |
| `UNIT` | Единица измерения | строка | «₽ / страница» |

## 5. Списки значений (XML_ID)

XML_ID — стабильный ключ значения. В конфиге демо-контента указывается
именно он, миграция переводит его в числовой ID.

| Свойство | XML_ID → значение |
|---|---|
| `news.TAGS` | `books` Книги, `digital` Цифровые ресурсы, `events` События, `kids` Дети, `science` Наука, `library` Библиотека |
| `events.CATEGORY` | `literature` Литература, `children` Для детей, `tech` Технологии, `lecture` Лекции |
| `events.FORMAT` | `offline` Офлайн, `online` Онлайн, `hybrid` Гибрид |
| `books.AGE_LIMIT` | `0plus` 0+, `6plus` 6+, `12plus` 12+, `16plus` 16+, `18plus` 18+ |
| `books.AVAILABLE` | `available` В наличии, `reserved` Забронирована, `unavailable` Выдана |
| `*.COLOR` | `primary` Синий, `green` Зелёный, `sky` Голубой, `pink` Розовый, `orange` Оранжевый |

Цвет в шаблоне превращается в класс: `primary` → `icon-tile--primary`,
`collection-card--primary`, `bg-grad-primary`.

## 7. Как страницы получают данные

В коде страницы не должно быть чисел вроде `'IBLOCK_ID' => 2`: на другой
установке это будет другой инфоблок. Используйте поиск по коду.

### 7.1. Готовый помощник

`db/lib/helpers.php` содержит `nlb_iblock_id('news')`, но подключать его на
каждой странице не нужно. Для продакшена удобнее один раз создать
`local/php_interface/include/nlb_db.php`:

```php
<?php
if (!defined('B_PROLOG_INCLUDED') || B_PROLOG_INCLUDED !== true) {
    die();
}

function nlb_iblock_id(string $code): int
{
    static $cache = [];
    if (isset($cache[$code])) {
        return $cache[$code];
    }
    $id = 0;
    $res = CIBlock::GetList([], ['CODE' => $code, 'CHECK_PERMISSIONS' => 'N']);
    if ($row = $res->Fetch()) {
        $id = (int)$row['ID'];
    }
    return $cache[$code] = $id;
}
```

и подключить его в `local/php_interface/init.php`:

```php
require_once __DIR__ . '/include/nlb_db.php';
```

### 7.2. Вызов компонента

```php
$APPLICATION->IncludeComponent('bitrix:news.list', 'news_cards', [
    'IBLOCK_TYPE' => 'nlb_content',
    'IBLOCK_ID' => nlb_iblock_id('news'),
    'NEWS_COUNT' => 4,
    'SORT_BY1' => 'ACTIVE_FROM',
    'SORT_ORDER1' => 'DESC',
    'FIELD_CODE' => ['NAME', 'PREVIEW_TEXT', 'PREVIEW_PICTURE', 'ACTIVE_FROM', 'DETAIL_PAGE_URL'],
    'PROPERTY_CODE' => ['AUTHOR', 'TAGS', 'READ_TIME'],
    'CHECK_DATES' => 'Y',
    'SET_TITLE' => 'N',
    'CACHE_TYPE' => 'A',
    'CACHE_TIME' => 3600,
], false, ['HIDE_ICONS' => 'Y']);
```

Полные примеры для каждой страницы — `bitrix-integration.md`, § 3–12.
Шаблоны компонентов (`news_cards`, `events_cards`, `books_cards`, `article`,
`event`) — в `../local/templates/nlb_bootstrap/components/bitrix/`.

### 7.3. Количество вместо счётчиков

Отдельных счётчиков (просмотры, заказы, «сколько раз воспользовались»)
в структуре нет. На сайте показывается только **количество активных
элементов**:

```php
nlb_iblock_count('services');  // 6 из демо-набора
nlb_counts();                  // все шесть инфоблоков сразу
```

`nlb_iblock_count()` кеширует результат на время запроса и не тянет строки:
используется `SelectedRowsCount()` результата `CIBlockElement::GetList`.
Для больших каталогов этого достаточно; отдельный модуль статистики не нужен.

Если понадобится именно счётчик просмотров — это новая задача (модуль
«Статистика» или внешняя аналитика), а не поле в инфоблоке.

## 8. Демо-контент

| Инфоблок | Элементов | Даты | Картинки |
|---|---|---|---|
| `news` | 10 | октябрь–ноябрь 2026 | `news-1…4`, `hero-1…3` |
| `events` | 6 | 6–29 ноября 2026 | `event.jpg` |
| `books` | 12 | с 1 сентября 2026 | нет (заглушка) |
| `collections` | 6 | с 1 сентября 2026 | нет |
| `services` | 6 | с 1 сентября 2026 | нет (иконки) |
| `printing` | 8 | с 1 сентября 2026 | `print-*.jpg` |

Тексты, цены, ISBN, телефоны и адреса — **демонстрационные**. Перед
публикацией их нужно заменить (бэклог, P0-9). Даты событий специально в
будущем относительно даты поставки: афиша должна выглядеть живой.

Картинки лежат в `assets/images/` шаблона; миграция копирует их в
`upload/` через `CFile::MakeFileArray`, поэтому после установки они
принадлежат сайту и не зависят от файлов шаблона.

## 9. Проверки и изменения

```bash
php db/lint.php      # конфиги без Битрикса: коды, XML_ID, даты, картинки, иконки
php db/run.php       # применить
php db/check.php     # сверить базу с конфигами
php db/tests/run.php # прогон миграций на заглушках ядра (17 проверок)
```

Добавить свойство:

1. описать в `db/config/iblocks.php` → `properties`;
2. `php db/lint.php` → `php db/run.php --only=003`;
3. добавить код в `PROPERTY_CODE` вызова компонента;
4. очистить кеш.

Добавить элемент: `db/config/data/<инфоблок>.php` с новым уникальным
`xml_id` → `php db/run.php --only=005`. Существующие элементы миграция не
перетирает — их правят в админке.

## 10. Ограничения

- **Не проверено на реальном ядре.** Ядра Битрикса на машине разработки нет
  (см. `Что доделать.txt`, P0-11). Логика миграций прогнана на заглушках
  (`db/tests`), синтаксис — `php -l`, структура — `db/lint.php`.
- Счётчиков услуг/просмотров нет: выводится только количество элементов
  (§ 7.3). Если нужна статистика — отдельная задача.
- Версия свойств — 2. При переводе существующего инфоблока с версии 1
  свойства переносятся ядром отдельной операцией.
- Демо-контент не претендует на библиографическую точность.
- Поисковый индекс после миграций нужно перестроить вручную
  (**Поиск → Переиндексация**).
