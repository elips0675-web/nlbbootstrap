# Установка шаблона в 1С-Битрикс

Документ рассчитан на «Управление сайтом» без composer и без доступа к
командной строке. Все пути в админке — для стандартного интерфейса
`/bitrix/admin/`.

## 1. Что нужно до начала

- установленный Битрикс, доступ в админку с правами администратора;
- доступ к файлам сайта (FTP/SFTP/панель хостинга/SSH) — шаблон и `db/`
  копируются в корень сайта;
- версия PHP 8.0+ (синтаксис и конфиги проверены на 8.3.30 и 8.5.12);
- доступ к MySQL (создаётся инфоблоками, своих таблиц миграции не заводят);
- очищенный кеш после установки.

Проверка версии: **Настройки → Проверка системы** (блок «Версия PHP») или
через хостинг/SSH (`php -v`).

## 2. Копирование файлов

Шаблон ставится **поверх установленного Битрикса**: в корне сайта уже должны
лежать `bitrix/` и `upload/`. Разворачивать репозиторий в пустой каталог
бесполезно — получится набор страниц без ядра.

| Что копировать | Куда | Зачем |
|---|---|---|
| `local/` целиком | `<DOCUMENT_ROOT>/local/` | шаблон, `php_interface/` (`init.php` и 8 файлов `include/`), `ajax/` (поиск, чат, push) |
| страницы и разделы | `<DOCUMENT_ROOT>/` | `index.php`, `404.php`, `urlrewrite.php`, `sitemap.php`, каталоги `about/`, `news/`, `events/`, `books/`, `services/`, `printing/`, `collections/`, `contacts/`, `feedback/`, `subscribe/`, `search/`, `personal/`, `auth/` |
| `db/` | `<DOCUMENT_ROOT>/db/` | миграции, конфиги, проверки |
| `tools/` | `<DOCUMENT_ROOT>/tools/` | сборка поискового индекса и картинок, VAPID-ключи, selftest'ы |
| `api/` | `<DOCUMENT_ROOT>/api/` | обработчик заявок из Telegram |

Не копировать и не перезаписывать: `bitrix/`, `bitrix/.settings.php`,
`bitrix/php_interface/dbconn.php`, `upload/`, корневой `.htaccess`.

Корневого `.htaccess` в репозитории нет: правила rewrite для Apache создаёт
установщик Битрикса. `urlrewrite.php` при этом **не пустой** — в нём семь
правил ЧПУ (новости, события, услуги, печать, книги, коллекции, `sitemap.xml`).

На nginx `.htaccess` не читается, поэтому служебные каталоги закрываются в
конфиге сайта:

```nginx
location ^~ /db/    { deny all; }
location ^~ /tools/ { deny all; }
```

Структура шаблона:

```
<DOCUMENT_ROOT>/
└── local/
    └── templates/
        └── nlb_bootstrap/
            ├── header.php
            ├── footer.php
            ├── styles.css
            ├── script.js
            ├── .description.php
            ├── assets/
            └── components/
```

Требования к правам (Linux): каталоги `755`, файлы `644`, владелец — тот же,
что у остальных файлов сайта (обычно `www-data` или пользователь хостинга).
Не ставьте `777`.

### Если на сайте уже есть инфоблоки

Код инфоблока в Битриксе не уникален: `news` может принадлежать
другому типу (демо-контент другой редакции, чужой шаблон). Поэтому
`nlb_iblock_id()` фильтрует по `CODE` **и** `IBLOCK_TYPE_ID`
(`db/lib/helpers.php:111-137`), а найденную строку сверяет по типу повторно.
Рантайм-копия (`local/php_interface/include/nlb_db.php:24-50`) отсеивает всё,
что лежит вне типов с префиксом `nlb_`.

Чужой инфоблок больше не подменяет свой: миграция создаёт собственный, а
`php db/check.php` сообщает о занятом коде
(`db/check.php:57-59`, «чужой инфоблок ID N в типе … — код занят»). Такой
инфоблок нужно удалить или переименовать в его `CODE` до повторного запуска:
структура установки должна быть однозначной. Поведение закреплено тестом
`db/tests/iblock-collision.php`.

### Изображения и адаптивные варианты

Демо-картинки лежат в `local/templates/nlb_bootstrap/assets/images/`. Кроме
исходного JPG рядом должны быть `.webp`, `.avif` и ширины `-480`, `-960`,
`-1280` (если исходник шире). Они уже в репозитории. После замены фото:

```
php tools/build-image-variants.php
php tools/build-preview-pages.php
```

Первый скрипт требует PHP с GD и поддержкой WebP/AVIF (`imagewebp`,
`imageavif`); без неё он завершится с понятной ошибкой. Если вариантов нет,
`nlb_picture()` выведет обычный `<img>` — страница не сломается.

### Если каталога `local/` нет

1. Создайте `<DOCUMENT_ROOT>/local/templates/`.
2. Убедитесь, что в `<DOCUMENT_ROOT>/bitrix/.settings.php` нет запрета на
   подключение `local` (ключ `cache`/`exception_handling` его не задаёт).
3. В Битриксе с 2021 года `local/` подключается автоматически.

### Альтернатива: `bitrix/templates/`

Можно положить шаблон в `bitrix/templates/nlb_bootstrap/` — ядро его увидит.
Но тогда файлы попадут в зону обновлений продукта, и при обновлении их легко
потерять. Для своих шаблонов используйте **только** `local/`.

### База данных и демо-контент

Рядом с `local/` в корень сайта копируется каталог `db/`:

```
<DOCUMENT_ROOT>/
├── bitrix/
├── local/
├── db/          ← миграции, конфиги, проверки
├── tools/       ← сборка индекса и картинок
├── api/         ← обработчик заявок из Telegram
└── menu/        ← появится после шага 006
```

Затем (CLI, из корня сайта):

```bash
php db/lint.php                    # проверка конфигов без ядра
php db/run.php                     # 12 шагов: типы, инфоблоки, свойства, разделы, контент, меню
php db/check.php                   # сверка базы с конфигами
php tools/build-search-index.php   # индекс мгновенной выдачи
```

Создаётся 9 инфоблоков (новости, события, подарочные наборы, сувениры, услуги,
печать, заявки, брони, заказы), 65 свойств, 12 разделов, 91 демо-элемент, файлы `/menu/top.menu.php`,
`/menu/bottom.menu.php`, `/services/.left.menu.php` и
`/printing/.left.menu.php`. Повторный запуск безопасен: дубли не создаются.

`db/.htaccess` закрывает каталог от веба (`Require all denied`), поэтому
`/db/run.php?run=yes` и `/db/check.php` на Apache отвечают 403 — это защита, а
не поломка. Веб-режим возможен только с временным разрешением каталога, и
разрешение нужно вернуть; на nginx то же делает `deny all` из §2. Откат:
`php db/rollback.php --yes`.

Полное описание — `../db/README.md`, модель данных — `db.md`. Выполнять этот
шаг можно и до, и после выбора шаблона: он не меняет настройки сайта (шаг 007
с привязкой шаблона запускается только с флагом `--set-template`).

### Поиск: два индекса

`db/search/index.json` лежит в репозитории собранным из демо-данных (ID
документов вида `services:nlb-srv-005`). На живой базе ID другие, поэтому после
миграций индекс пересобирают:

```bash
php tools/build-search-index.php          # собрать из инфоблоков
php tools/build-search-index.php --check  # сверить с источниками
```

На живой базе `--check` сверяет `db/config/data/*.php`, а не БД. Правки в
админке индекс не обновляют: хука `OnAfterIBlockElement*` пока нет, пересборка
запускается вручную или по cron.

Мгновенная выдача в модалке шапки — это BM25 по `index.json`. Страница
`/search/` использует штатный `bitrix:search.page` со своим индексом модуля
«Поиск». Это два разных поиска: после наполнения инфоблоков запустите
**Поиск → Переиндексация**, иначе `/search/` останется пустым.

## 3. Выбор шаблона у сайта

1. **Настройки → Настройки продукта → Сайты → Список сайтов**.
2. Нажмите на сайт (или «Изменить»).
3. Поле **Шаблон сайта** → выберите `NLB Bootstrap — библиотека`.
4. **Сохранить**.

Название берётся из `.description.php`:

```php
'NAME' => 'NLB Bootstrap — библиотека',
'DESCRIPTION' => 'Адаптивный шаблон на Bootstrap 5.3: ...',
```

Если шаблона нет в списке:

- проверьте путь: `local/templates/nlb_bootstrap/.description.php`;
- проверьте, что файл начинается с `<?php` и не имеет BOM;
- проверьте права на чтение;
- очистите кеш (п. 5).

### Шаблон для отдельного раздела

Условие «свой шаблон для раздела» задаётся в настройках сайта, вкладка
**Шаблоны** → «Использовать свой шаблон для разделов» либо через
`$APPLICATION->SetTemplateID()` в `init.php`. Для старта это не нужно.

## 4. Тип меню `top`

Шаблон ждёт меню с кодом `top` (`header.php:144`).

1. **Настройки → Настройки продукта → Сайты → Типы меню**.
2. **Добавить тип меню**:

| Поле | Значение |
|---|---|
| Код | `top` |
| Название | Верхнее меню |
| Тип меню | `top` |

3. **Сохранить**.

4. **Контент → Структура сайта** → корневой раздел сайта (иконка «Меню» или
   вкладка **Меню** в форме раздела).
5. Выберите тип `top` → **Добавить пункт**:

| Текст | Ссылка | Сортировка |
|---|---|---|
| Главная | `/` | 10 |
| Новости | `/news/` | 20 |
| События | `/events/` | 30 |
| Услуги | `/services/` | 40 |
| Печать | `/printing/` | 50 |
| Каталог продукции | `/books/` | 60 |
| Контакты | `/contacts/` | 70 |

Ссылки должны вести на существующие страницы, иначе будет 404. Пока тип `top`
не создан, шаблон показывает демо-меню
(`local/templates/nlb_bootstrap/components/bitrix/menu/top_bootstrap/template.php:46`)
— это не ошибка, но в продакшене демо-меню быть не должно.

### Второй уровень и выпадающие списки

Шаблон уже поддерживает второй уровень: `MAX_LEVEL => '2'`,
`CHILD_MENU_TYPE => 'left'`. Подпункты для «Услуг» и «Печати» копирует
миграция 011:

```bash
php db/run.php --only=011
```

Появятся `/services/.left.menu.php` (8 услуг + «Все услуги») и
`/printing/.left.menu.php` (8 печатных услуг + «Все услуги печати»). В админке
их правит контент-менеджер: **Структура сайта → раздел → Меню → тип `left`**.
Существующие файлы миграция не перезаписывает; сбросить к исходным —
`--force`.

Добавить подпункты другим разделам: создайте `.left.menu.php` в каталоге
раздела (пункт «Все …» первым, чтобы страница раздела оставалась доступной с
телефона) и очистите кеш.

## 5. Очистка кеша

Порядок:

1. **Настройки → Автокеширование → Очистить весь кеш**.
2. На публичной странице нажмите **Сбросить кеш** на панели Битрикс (если
   включён режим правки).
3. Обновите страницу с `Ctrl+F5` (сброс кеша браузера).

Без очистки кеша шаблон, меню и CSS не применятся — Битрикс хранит
скомпилированные шаблоны компонентов и HTML-кеш страниц.

## 6. Главная страница

Вариант A — демо-лендинг:

1. Скопируйте `demo/index.php` в `<DOCUMENT_ROOT>/index.php` (предварительно
   сохраните старый файл).
2. Откройте главную.

Вариант B — своя главная:

1. **Контент → Структура сайта** → корневой раздел.
2. Создайте страницу `index.php` (или откройте существующую).
3. Вставьте нужные секции из `demo/index.php` в режиме правки или в файл.
4. Заголовок и описание задайте через **Свойства страницы**:
   - `TITLE` — заголовок вкладки;
   - `description` — meta description;
   - `keywords` — при необходимости.

`demo/index.php` уже вызывает:

```php
require $_SERVER['DOCUMENT_ROOT'] . '/bitrix/header.php';
$APPLICATION->SetTitle('Библиотека 2026 — центр знаний');
$APPLICATION->SetPageProperty('description', '...');
```

## 7. Уведомления: письма и Web Push

Письма о заявках настраиваются миграцией `008_requests.php` (обращения,
брони, заказы) и `012_booking_mail.php` (бронь: сотруднику и клиенту).
Шаблоны создаются в **Настройки → Настройки продукта → Почтовые события**;
если почта на хостинге не настроена, заявка всё равно сохраняется в инфоблоке.

Web Push (уведомление о новой брони в браузере сотрудника) — необязательный
модуль. Ключи создаются один раз:

```bash
php tools/gen-vapid.php
```

Скрипт пишет `local/php_interface/include/nlb_push_keys.php` — файл в git
не попадает. Дальше администратор открывает `/personal/` и включает
уведомления; подписка привязана к устройству. Без файла ключей карточка
не показывается, а сайт работает как обычно.

Проверка без сети и без Битрикса:

```bash
php tools/push-selftest.php
```

> Push и service worker требуют **HTTPS**. На голом HTTP браузер не выдаёт
> `PushManager`, и включить уведомления нельзя.

## 8. Проверка после установки

| Что проверить | Ожидаемо |
|---|---|
| Главная | шапка, hero-карусель, 8 карточек печати, подвал |
| Исходный код страницы | есть `<link ... bootstrap.min.css>` и `styles.css` |
| Консоль браузера | нет 404 по `assets/` |
| Внутренняя страница | хлебные крошки под шапкой |
| Мобильная ширина (≤ 991px) | бургер раскрывает меню, пункты крупные |
| `Ctrl+K` | открывается модалка поиска |
| Мгновенная выдача | подсказки находят элемент, созданный в админке |
| Штатный `/search/` | после **Поиск → Переиндексация** находит материалы |
| Инфоблоки свои | в `db/logs/` нет строк «инфоблок … уже есть» |
| Админ-панель | видна сверху (для администратора) |
| Кеш | после правки шаблона изменения видны |

Проверки базы выполняются только из CLI (`php db/check.php`): каталог `db/`
закрыт от веба файлом `db/.htaccess`, и на Apache адрес `/db/check.php`
отвечает 403.

Если что-то не так — таблица ниже.

## 9. Диагностика

| Симптом | Причина | Решение |
|---|---|---|
| Шаблон не в списке | нет `.description.php`, BOM, права | проверить файл и права, очистить кеш |
| Сайт белый | синтаксическая ошибка PHP | включить вывод ошибок, `php -l` на сервере |
| Нет стилей | 404 на `assets/css/bootstrap.min.css` | проверить путь `SITE_TEMPLATE_PATH`, права |
| Нет меню, видно «Главная / Новости / …» | не создан тип `top` | создать тип и пункты (п. 4) |
| Меню не меняется | кеш компонента | очистить кеш, проверить `MENU_CACHE_TIME` |
| Крошки не видны | вы на главной | это штатно: крошки скрыты на `/` |
| Крошки пустые | у страницы нет цепочки навигации | задать «Привязка к разделу»/навигацию |
| Иконки не рисуются | SVG-спрайт вырезан оптимизатором | не удалять блок `symbol` из `header.php` |
| Модалки не открываются | не загрузился `bootstrap.bundle.min.js` | проверить 404 и порядок скриптов |
| «Липкая» шапка перекрывает якорь | нет `scroll-margin-top` у цели | добавить `style="scroll-margin-top:90px"` или класс |
| 403 на `/db/run.php?run=yes` | `db/.htaccess` закрывает каталог от веба | запускать `php db/run.php` из CLI |
| 404 на `/news/<код>/` | Apache без `.htaccess` с правилами rewrite | правила Битрикса или `try_files` в nginx |
| Подсказки поиска ведут на старые адреса | индекс собран из демо-данных | `php tools/build-search-index.php` |
| Инфоблоки наполнены «не тем» | совпал `CODE` с чужим инфоблоком | удалить демо-инфоблоки и повторить `php db/run.php` |
| После обновления ядра всё сломалось | шаблон лежит в `bitrix/templates` | перенести в `local/templates` |

## 10. Удаление

1. Выберите у сайта другой шаблон.
2. Очистите кеш.
3. Удалите `local/templates/nlb_bootstrap/`.
4. Удалите тип меню `top`, если он больше не нужен (**Типы меню** →
   удалить; пункты меню удалятся вместе с типом).
