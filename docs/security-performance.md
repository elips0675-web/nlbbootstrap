# Безопасность и производительность

## 1. Безопасность шаблона

Шаблон — это представление. Он не хранит данные, но может стать дырой, если
выводить пользовательский контент без экранирования.

### 1.1 Экранирование

Правило: **любой текст из инфоблока/формы/`$_GET` — через
`htmlspecialcharsbx()`**.

```php
<!-- правильно -->
<a href="<?= htmlspecialcharsbx($arItem['DETAIL_PAGE_URL']) ?>">
    <?= htmlspecialcharsbx($arItem['NAME']) ?>
</a>

<!-- неправильно: XSS через название элемента -->
<a href="<?= $arItem['DETAIL_PAGE_URL'] ?>"><?= $arItem['NAME'] ?></a>
```

Исключение — поля, которые Битрикс уже подготовил как HTML
(`PREVIEW_TEXT`, `DETAIL_TEXT` после обработчика). Их выводят как есть, но
только если контент доверенный (редактор). Для пользовательских полей — всегда
экранирование.

В шаблоне уже экранированы: пункты меню
(`components/bitrix/menu/top_bootstrap/template.php:123`), крошки
(`components/bitrix/breadcrumb/bootstrap/template.php:24`), ссылки в демо-разметке.

### 1.2 Файлы и права

| Объект | Права |
|---|---|
| каталоги `local/` | `755` |
| файлы `*.php`, `*.css`, `*.js` | `644` |
| изображения | `644` |
| `bitrix/.settings.php` | `644`, владелец — веб-сервер |

Не ставить `777`. Не хранить в шаблоне `.env`, ключи, пароли, дампы.

### 1.3 Формы

- CAPTCHA включена: `USE_CAPTCHA => 'Y'` в `iblock.element.add.form`;
- серверная валидация обязательна: согласие и занятый слот проверяет
  `OnBeforeIBlockElementAdd` в `nlb_forms.php`, даже при отключённом JS;
- согласие на обработку персональных данных — отдельный checkbox, ссылка на
  политику;
- e-mail получателя — реальный ящик, не `example.by`;
- логи отправки — **Настройки → Настройки продукта → Почтовые события →
  Журнал**.

### 1.4 Доступ к админке

- отдельная учётная запись администратора, не `admin/admin`;
- двухфакторная аутентификация (модуль «Главный модуль» → пользователи);
- ограничение доступа к `/bitrix/admin/` по IP, если возможно;
- журнал входа — **Настройки → Пользователи → Журнал событий**.

### 1.5 Заголовки безопасности

Ставятся кодом в `local/php_interface/include/nlb_security.php`, вызов — из
`local/php_interface/init.php`. Работает и на shared-хостинге, где нет доступа
к конфигу nginx/Apache.

| Заголовок | Значение |
|---|---|
| `X-Content-Type-Options` | `nosniff` |
| `X-Frame-Options` | `SAMEORIGIN` |
| `Referrer-Policy` | `strict-origin-when-cross-origin` |
| `Permissions-Policy` | камера, микрофон, геолокация, оплата, USB — запрещены |
| `Cross-Origin-Opener-Policy` | `same-origin-allow-popups` |
| `Cross-Origin-Resource-Policy` | `same-origin` |
| `Strict-Transport-Security` | `max-age=31536000` (только при HTTPS) |
| `Content-Security-Policy` | только для публичных страниц, см. ниже |

CSP по умолчанию:

```
default-src 'self'; base-uri 'self'; form-action 'self'; frame-ancestors 'self';
object-src 'none'; img-src 'self' data: blob:; font-src 'self' data:;
style-src 'self' 'unsafe-inline'; script-src 'self' 'unsafe-inline';
connect-src 'self'; manifest-src 'self'; worker-src 'self'
```

`'unsafe-inline'` нужен: Битрикс и шаблон выводят строчные скрипты
(инициализация компонентов, счётчики форм). Админка (`/bitrix/`,
`ADMIN_SECTION`) из-под CSP выведена — иначе панель ломается.

Отключить CSP, если подключается внешняя аналитика:

```php
// local/php_interface/init.php, до require хелперов
define('NLB_CSP', false);
```

### 1.6 robots.txt, sitemap и закрытые каталоги

`robots.txt` в корне закрывает служебные разделы и параметры фильтров:

```
User-agent: *
Allow: /
Disallow: /bitrix/
Disallow: /db/
Disallow: /tools/
Disallow: /search/
Disallow: /auth/
Disallow: /personal/
Disallow: /*?section=
Disallow: /*?past=
Disallow: /*?PAGEN

Clean-param: section&past&PAGEN_1 /

Sitemap: https://example.by/sitemap.xml
```

`/local/templates/` и `/upload/` не закрываются: иначе поисковик не увидит CSS
шаблона и картинки контента.

Карта сайта — `sitemap.php`, отдаётся по `/sitemap.xml` через правило в
`urlrewrite.php`. Домен берётся из запроса, `lastmod` — из даты изменения файла
раздела, поэтому перенос на прод ничего не ломает. Элементы инфоблоков в карту
не перечисляются: после установки ядра их добавит штатный генератор
(«Настройки → Поиск → Карта сайта»), иначе список пришлось бы дублировать.

Миграции и служебные скрипты закрыты от веба: `db/.htaccess` и `tools/.htaccess`
с `Require all denied` (Apache 2.4 + fallback для 2.2). Для nginx добавьте
в конфиг сайта:

```nginx
location ^~ /db/    { deny all; }
location ^~ /tools/ { deny all; }
```

Дополнительно на уровне сервера (Apache):

```apache
<FilesMatch "\.(env|log|sql|bak|ini)$">
    Require all denied
</FilesMatch>
```

Для nginx — запрет на `*.log`, `*.sql`, `.env`, `.git`.

### 1.7 Что не должно попасть в прод

- демо-контакты `info@example.by`, `+375 (17) 300-00-00`;
- демо-соцсети `t.me/example`;
- демо-реквизиты (УНП `000000000`, счёт `BY00 XXXX…`);
- неподключённые формы (если миграция `008` не выполнена);
- демо-меню (если тип `top` не создан);
- демо-изображения Unsplash без проверки лицензии на конкретное фото.

Демо-данные продублированы в JSON-LD (`nlb_seo_jsonld()`): адрес, телефон,
e-mail и `sameAs` правятся в двух местах — `footer.php` и `nlb_seo.php`.

Список дублируется в `Что доделать.txt` как P0/P1.

### 1.8 Чат: фильтр на сервере

Браузерный `chatProblem()` (`script.js`) — проверка интерфейса, её обходит
отключённый JS или запрос мимо формы. Тот же вердикт считает
`local/php_interface/include/nlb_text_filter.php`, эндпоинт —
`local/ajax/chat.php` (`POST message` + `sessid`, ответ JSON). Текст
сообщения не пишется в лог и не сохраняется.

Списки и выражения обязаны совпадать: паритет проверяет
`node tools/check-filter-parity.mjs` на общем наборе фраз
`db/tests/fixtures/filter-cases.json`, сам фильтр — `php tools/filter-selftest.php`.
Тематические корни (`террор`, `насил`, `оружи`, `нарко`, `ненавиж`) пропускаются
при книжном контексте: «книги о ненависти» проходят, «я тебя ненавижу» — нет.

### 1.9 Поиск: индекс закрыт, запрос не логируется

Мгновенный поиск (`local/ajax/search.php`) отдаёт JSON по `GET q`: методы
кроме `GET` — `405`, пустой запрос — `400 empty_query`, длиннее 200 символов —
`400 query_too_long`, нет индекса — `503 index_unavailable`. Ответ помечен
`Cache-Control: no-store` и `X-Robots-Tag: noindex`: выдача зависит от
запроса, кешировать её на прокси нельзя.

Индекс `db/search/index.json` лежит в закрытом каталоге (`db/.htaccess`,
`robots.txt`), наружу не отдаётся: это список всех документов сайта с длинами,
полезный для подготовки атаки и бесполезный для поисковика. Запрос
пользователя не пишется ни в лог, ни в статистику — по поисковым фразам
восстанавливаются интересы человека; в `$_GET` он живёт только на время
запроса.

Текст документов выводится в модалку через `textContent`, не через
`innerHTML`: сниппет — это кусок текста из инфоблока, и он не должен уметь
становиться разметкой. Ссылки берутся из индекса, а не из запроса, поэтому
подставить внешний адрес через `q` нельзя.

Свежесть индекса — по пофайловым sha256 источников (`db/config/data/*.php`,
`db/config/iblocks.php`, `db/search/pages.json`), а не по дате файла: дата
врёт после клона и восстановления из архива. Расхождение — падение
`php tools/build-search-index.php --check` и §11.2 в `node tools/check-template.mjs`.

## 2. Производительность

### 2.1 Что сделано

| Мера | Где | Эффект |
|---|---|---|
| Bootstrap локально, без CDN | `assets/` | нет лишнего DNS/TLS |
| Нет jQuery, нет сборки | `script.js` | 72,0 КБ своего JS |
| Картинки пережаты и обрезаны под пропорции вывода | `assets/images/` | 20 файлов, 2002 КБ (базовые 17: 3722 → 1813 КБ, −51 %) |
| WebP/AVIF и ширины 480/960/1280 рядом с JPG | `assets/images/` | 162 файла: JPG 3885 КБ, WebP 2331 КБ, AVIF 2033 КБ |
| `<picture>` + `srcset`/`sizes` | `nlb_picture()`, `nlb_media.php` | браузер берёт AVIF/WebP и ширину под слот |
| Шрифты системные, Google Fonts убран | `header.php`, `styles.css` | минус внешний запрос, офлайн работает |
| `loading="lazy"` + `decoding="async"` ниже первого экрана | шаблоны, `nlb_cards` | меньше декодирования до LCP |
| `fetchpriority="high"` у первого hero | `index.php` | hero грузится раньше |
| `preload` для `styles.css` | `header.php` | CSS не ждёт разбора тела |
| Service worker кеширует оболочку | `sw.js` | повторный визит без запросов к статике |
| Кеш компонентов | `CACHE_TYPE => 'A'` | TTFB после прогрева |
| Reveal через IntersectionObserver | `script.js` | нет скролл-обработчиков на элемент |
| `prefers-reduced-motion` | `styles.css` | анимации отключаются |

### 2.2 Картинки

Скрипт `tools/optimize-images.ps1` кадрирует по центру под фактические пропорции
(CSS использует `object-fit: cover`, поэтому лишние края всё равно обрезались),
уменьшает до нужной ширины и подбирает качество JPEG под целевой вес.

Результат прогона:

| Файл | Было | Стало | Формат вывода |
|---|---|---|---|
| `hero-1.jpg` | 599 КБ | 191 КБ | 1200×675 (16:9) |
| `hero-2.jpg` | 377 КБ | 115 КБ | 1200×675 |
| `hero-3.jpg` | 93 КБ | 76 КБ | 1200×675 |
| `event.jpg` | 553 КБ | 162 КБ | 1000×667 (3:2) |
| `news-1.jpg` | 431 КБ | 146 КБ | 1000×667 |

| остальные `print-*` | 42–186 КБ | 42–116 КБ | 900×675 |
| **всего (17 файлов)** | **3722 КБ** | **1813 КБ** | — |
| 3 фото услуг (добавлены) | 226 КБ | 190 КБ | 1000×667 (3:2) |
| **всего (20 файлов)** | **3948 КБ** | **2002 КБ** | — |

`og-cover.jpg` (1200×630) — карточка для соцсетей, генерируется из `hero-1.jpg`.

Адаптивные варианты собирает `php tools/build-image-variants.php` (GD с
`imagewebp`/`imageavif`): к каждому JPG добавляются `.webp`, `.avif` и ширины
`480`, `960`, `1280`, если исходник шире. Всего 20 исходников и 142 варианта:
JPG 3885 КБ, WebP 2331 КБ, AVIF 2033 КБ. На странице остаётся один JPG-фолбэк,
остальное браузер выбирает сам; ПК получает десктопную ширину, телефон — 480px.

Что осталось на прод:

1. `Cache-Control: public, max-age=31536000, immutable` для `assets/`
   (nginx/Apache — конфиг сервера, из PHP не задаётся);
2. Lighthouse на живом домене: варианты и `srcset` локально проверены по
   разметке, но реальные метрики снимаются только на HTTPS-стенде.

### 2.3 Шрифт

Внешний Google Fonts убран: остался системный стек
`"Manrope", "Inter", "Segoe UI", system-ui, …` (`styles.css`). Manrope
подхватится, если установлен в системе; иначе используется системный шрифт —
внешний запрос, FOUT и зависимость от доступности Google исчезают.

Если нужен именно Manrope — положите WOFF2 в `assets/fonts/`, объявите
`@font-face` с `font-display: swap` и добавьте файл в список предзагрузки
`sw.js` (`SHELL`). Подробнее — `customization.md`, п. 3.

### 2.4 Кеширование

| Уровень | Настройка |
|---|---|
| Битрикс, компоненты | `CACHE_TYPE => 'A'`, `CACHE_TIME => 3600` |
| Битрикс, страницы | «Автокеширование» → включено |
| Service worker | `nlb-shell-v1`: CSS, JS, иконки, `offline.html` |
| Браузер, статика | `expires 1y` для `assets/` (настраивается на сервере) |
| Сервер | gzip/brotli, HTTP/2 |

После правки шаблона — **Настройки → Автокеширование → Очистить весь кеш**.
После правки `sw.js` — увеличить `VERSION` в первой строке файла, иначе у
посетителей останется старый кеш.

### 2.5 CSS/JS

- `styles.css` 78,8 КБ (было 36 КБ: добавлены секции 16–17 — внутренние
  страницы и баннеры) — минификация на продакшене даст ~15 %, не критично;
- `bootstrap.min.css` 227 КБ — приемлемо; кастомная сборка только с нужными
  компонентами уменьшит файл в 2–3 раза, но потребует Sass;
- `script.js` 72,0 КБ, `pwa.js` и `consent.js` по ~3 КБ — грузятся в конце тела.

### 2.6 Метрики

Проверять на живом сайте (локально не снимались — нужен домен и HTTPS):

- Lighthouse — Performance ≥ 90 на десктопе, ≥ 75 на мобильном;
- LCP < 2.5 c, CLS < 0.1, INP < 200 ms;
- TTFB < 300 ms после прогрева кеша.

Главные оставшиеся риски: отсутствие кеша Битрикса на старте (TTFB), 227 КБ
Bootstrap без кастомной сборки, нет `Cache-Control` для `assets/` на сервере.

## 3. Бэкапы и обновления

- бэкап файлов и БД перед установкой шаблона и перед обновлением ядра;
- шаблон в `local/` не перезаписывается обновлениями — это плюс;
- при обновлении Bootstrap — заменить оба файла и прогнать `qa-checklist.md`;
- хранить копию `local/templates/nlb_bootstrap/` в git (репозиторий этого
  каталога).

## 4. Логи и мониторинг

- **Настройки → Инструменты → Журнал событий** — ошибки PHP;
- `bitrix/modules/main/tools/cron_events.php` — агенты (подписка, рассылки);
- access-логи сервера — 404 на `assets/`, попытки входа в админку;
- uptime-мониторинг главной и `/bitrix/admin/` (внешний сервис).

## 5. Инциденты

| Симптом | Первое действие |
|---|---|
| Белый экран после правки | вернуть файл из бэкапа, включить `display_errors` на стенде |
| Массовые 404 на статику | проверить `SITE_TEMPLATE_PATH` и права |
| Всплеск нагрузки | проверить кеш, индексы инфоблоков, размер картинок |
| Подозрение на взлом | сменить пароли, проверить `local/`, `upload/`, cron, `.htaccess` |
| Письма не уходят | журнал почтовых событий, настройки модуля «Почта», SMTP |
