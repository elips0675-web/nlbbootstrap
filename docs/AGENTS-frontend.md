# AGENTS-frontend — правила CSS и JS

## 1. Стек

- CSS: Bootstrap 5.3.3 (вендор) + `styles.css` (наш, 3 785 строк).
- JS: `bootstrap.bundle.min.js` (вендор) + `script.js` (наш, IIFE, ES5+).
- Без Sass, PostCSS, Tailwind, jQuery, сборщиков.
- Целевые браузеры: последние 2 версии Chrome, Firefox, Safari, Edge; мобильные
  Safari/Chrome. IE11 не поддерживается (Bootstrap 5).

## 2. CSS: порядок и каскад

```
bootstrap.min.css → styles.css
```

Правила:

1. Новые стили — только в `styles.css`, в конец соответствующего раздела
   (нумерация 1–15 в шапке файла).
2. Не добавлять `<style>` на страницу, кроме одноразовой отладки.
3. Специфичность — минимальная достаточная. Вложенность — максимум 2 уровня
   (`.site-footer .brand-tag`).
4. `!important` — только для `.visually-hidden`, `.text-white-75` и
   `@media print`.
5. Не переопределять `.btn`, `.form-control` глобально без причины: это
   затронет все страницы.
6. Медиа-запросы — в разделе 14, по убыванию ширины (`max-width`), плюс
   `min-width` для прогрессивных улучшений (карточки печати).
7. `@media print` — в конце файла.

## 3. Именование

| Тип | Схема | Пример |
|---|---|---|
| Блок | семантика или `nlb-` | `.hero`, `.nlb-card` |
| Элемент | `__` | `.nlb-card__media`, `.nlb-card__body` |
| Модификатор | `--` | `.collection-card--blue`, `.section--soft` |
| Состояние | `is-` | `.is-open`, `.is-scrolled`, `.is-visible` |
| Утилита | Bootstrap | `.d-flex`, `.mt-3` |
| JS-хук | `data-*` | `data-reveal`, `data-scroller` |

Не использовать: `#id` для стилей (только для якорей/JS), имена вида
`.block1`, `.red`, `.left`.

## 4. Токены

- цвета, радиусы, тени, градиенты — только через `var(--nlb-*)`;
- новый цвет → новая переменная в `:root` (`styles.css:12`) с комментарием;
- не хардкодить `#fff`/`#000` в новых правилах: есть `#fff` только там, где
  нужен именно белый (фон карточки), это допустимо;
- размеры — в `rem` (кроме 1px-границ и иконок в px);
- `clamp()` — для заголовков и hero.

## 5. JS: структура

`script.js` — один IIFE, `'use strict'`, 9 независимых модулей. Каждый модуль:

1. находит элемент;
2. если элемента нет — тихо выходит (`if (!el) return`);
3. навешивает обработчики;
4. не зависит от других модулей.

Правила:

- не добавлять библиотеки;
- не использовать `innerHTML` с пользовательскими данными;
- обработчики прокрутки — `{ passive: true }`;
- новые модули — в конец, с комментарием-номером;
- глобальные переменные не создавать (всё внутри IIFE);
- блок фильтра чата (`CHAT_BLOCKED` … `chatProblem`) держать между маркерами
  `/* nlb-chat-filter:start */` и `/* nlb-chat-filter:end */`: по ним гейт
  паритета отделяет фильтр от остального кода; после правки списков или
  выражений — `node tools/check-filter-parity.mjs` и
  `php tools/filter-selftest.php`, иначе сервер и браузер разойдутся молча;
- мгновенный поиск (раздел 7) работает только через `textContent`: заголовки
  и сниппеты приходят из текста документов, `innerHTML` здесь — XSS; адрес
  эндпоинта берётся из `data-search-endpoint` формы, а не собирается из
  `action` (иначе на сайте с `SITE_DIR` запрос уйдёт в 404); после правки
  блока — `php tools/search-selftest.php` и `node tools/check-template.mjs`;
- для Bootstrap-плагинов — `getOrCreateInstance`, не `new`;
- проверять `window.bootstrap` перед вызовом.

### Как добавить модуль

```js
/* ------------------------------------------------------------------
 * 10. Название модуля
 * ------------------------------------------------------------------ */
const el = doc.querySelector('[data-my-widget]');
if (el) {
    el.addEventListener('click', function () {
        // ...
    });
}
```

Добавьте `data-my-widget` в разметку и проверьте, что на страницах без этого
элемента ошибок нет.

## 6. Доступность

Обязательно:

- `aria-label` у иконочных кнопок;
- `aria-current="page"` у активного пункта;
- `aria-expanded` у раскрывашек (Bootstrap обновляет сам, FAB — вручную);
- `aria-hidden="true"` у декоративных SVG;
- `visually-hidden` для текста, который нужен скринридеру;
- `:focus-visible` не убирать;
- порядок заголовков: один `h1` на страницу, далее `h2`/`h3`;
- контраст текста ≥ 4.5:1 (крупного ≥ 3:1);
- `prefers-reduced-motion` — отключать анимации.

Нельзя:

- `outline: none` без замены;
- кликабельный `<div>` без `role`/`tabindex`/`keydown`;
- `alt` вида «картинка», «фото», «image1».

## 7. Производительность

- новые картинки — с `loading="lazy"` (кроме первого экрана);
- не подключать внешние шрифты/скрипты без необходимости;
- не добавлять тяжёлые анимации на `box-shadow`/`filter` в цикле;
- `will-change` — только точечно и временно;
- CSS-файл не должен расти больше ~50 КБ без причины;
- проверять Lighthouse после крупных изменений.

## 8. Локальная проверка

1. Запустить `php -S 127.0.0.1:8791 -t preview` и открыть
   `http://127.0.0.1:8791/`.
2. DevTools → Console: ошибок нет.
3. Network: 404 нет.
4. Пройти меню: `/services/`, `/news/`, `/events/`, `/printing/`, `/books/`,
   `/collections/`, `/contacts/`; открыть одну детальную страницу.
5. Responsive: 360 / 768 / 1440.
6. `Ctrl+K`, модалки, скроллер, FAB, «наверх», фильтры разделов.
7. `node tools/check-template.mjs` — exit 0.
8. Если трогали фильтр чата — `node tools/check-filter-parity.mjs` — 0 расхождений.
9. Если трогали поиск — `php tools/search-selftest.php` и
   `php tools/build-search-index.php --check` (индекс мог устареть).

Превью поиска не показывает: в статическом демо нет PHP, мгновенная выдача
там не работает, форма ведёт на карту сайта. Проверять поиск — на живом
Битриксе или через `php -S` по корню репозитория с ядром.

Страницы `preview/` собираются из `db/config/` командой
`php tools/build-preview-pages.php`. Если меняли разметку главной в
`preview/index.html`, синхронизируйте `demo/index.php`: превью — эталон,
демо — его Bitrix-версия (P1-7 в `Что доделать.txt`).

## 9. Чего не делать

- Не переносить Tailwind-классы из `../src/` — их нет в сборке.
- Не подключать второй CSS-фреймворк.
- Не использовать `document.write`, `eval`, `new Function`.
- Не вешать обработчики на `window` без `removeEventListener` в SPA-подобных
  сценариях (здесь страницы перезагружаются, но модули должны быть чистыми).
- Не менять `script.js` так, чтобы он падал при отсутствии элемента.
- Не коммитить минифицированные копии без исходника.

## 10. Обновление вендорных файлов

2. Заменить файлы в `assets/`.
3. Проверить: navbar, carousel, modal, collapse, forms, grid.
4. Обновить версию в `README.md`, `project-context.md`, `CHANGELOG.md`.
5. Прогнать `qa-checklist.md`, раздел A.
