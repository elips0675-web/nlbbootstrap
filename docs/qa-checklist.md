# QA-чеклист

Две части проверок: **A** — что можно проверить локально по статическому демо
`preview/`, **B** — что проверяется только на живом Битриксе. Пункты B нельзя
закрыть на машине без PHP/MySQL — это фиксируется в `Что доделать.txt`.

Дальше: **C** — регресс before/after, **D** — что считается дефектом,
**E** — что писать в отчёт, **F** — порядок работ на Docker-стенде
(синхронизация, миграции, приёмка, известные дефекты).

## A. Локально (превью)

Из каталога репозитория запустите `php -S 127.0.0.1:8791 -t preview` и откройте
`http://127.0.0.1:8791/`. Не открывайте `preview/index.html` по `file://`:
ссылки на каталоги и service worker там не работают. Проверяйте в Chrome/Edge и,
если есть, в Firefox.

### A1. Загрузка

- [ ] нет 404 в консоли (вкладка Network);
- [ ] нет ошибок JS в консоли;
- [ ] Bootstrap CSS и `styles.css` применились (кнопки скруглённые, hero тёмный);
- [ ] системный шрифт отображается без скачивания внешних файлов;
- [ ] изображения hero, новостей, печати видны;
- [ ] `/services/`, `/news/`, `/events/`, `/printing/`, `/books/`,
  `/collections/`, `/contacts/` открываются по прямым адресам.

### A2. Шапка

- [ ] топбар виден на ≥ 992px и скрыт на мобильном;
- [ ] логотип и подпись не переносятся;
- [ ] пункты меню имеют hover-фон;
- [ ] активный пункт подсвечен, в том числе на внутренних страницах;
- [ ] меню ведёт на страницы (`/news/`, `/services/`…), а не на якоря `#…`;
- [ ] иконки поиска/уведомлений/кабинета кликабельны;
- [ ] при прокрутке появляется тень у шапки;
- [ ] шапка остаётся сверху (sticky) и не перекрывает контент.

### A3. Hero-карусель

- [ ] 3 слайда, автопрокрутка ~7 секунд;
- [ ] индикаторы переключают слайды;
- [ ] стрелки работают на десктопе и скрыты на мобильном;
- [ ] текст читаем на каждом слайде (контраст);
- [ ] кнопка ведёт на `#services`/`#events`;
- [ ] на мобильном высота hero не обрезает заголовок.

### A4. Секции

- [ ] услуги: 8 карточек, 1/2/3 в ряд на 360/768/1440;
- [ ] печать: скроллер листается кнопками и пальцем, кнопки блокируются на краях;
- [ ] события: 3 карточки, дата в бейдже, метаданные с иконками;
- [ ] новости: 4 карточки, текст обрезан в 2 строки;

- [ ] партнёры: 5 плиток, hover;

- [ ] reveal-анимация срабатывает при прокрутке (и отключена при
      `prefers-reduced-motion`).

### A5. Подвал

- [ ] 4 колонки на десктопе, 2 на планшете, 1 на мобильном;
- [ ] ссылки «Читателям»/«Услуги» ведут на якоря;
- [ ] телефон и e-mail кликабельны;
- [ ] форма подписки: пустой e-mail → ошибка, корректный → уходит (в превью

## B. На живом Битриксе

Выполняется после установки (`installation.md`). Каждый пункт — с указанием,
где смотреть.

### B1. Установка

- [ ] шаблон есть в списке **Настройки → Настройки продукта → Сайты → Список
      сайтов → Шаблон сайта**;
- [ ] после выбора и очистки кеша главная открывается в новом оформлении;
- [ ] в исходном коде есть `bootstrap.min.css` и `styles.css` без 404;
- [ ] админ-панель видна сверху;
- [ ] `local/templates/nlb_bootstrap/` доступен на чтение, но не на запись
      всем.

### B2. Меню

- [ ] тип `top` создан;
- [ ] пункты ведут на существующие страницы;
- [ ] активный пункт подсвечивается на своей странице;
- [ ] при удалении пункта из админки он исчезает после сброса кеша;
- [ ] демо-меню не показывается (иначе тип `top` пуст).

### B3. Хлебные крошки

- [ ] на внутренней странице видны крошки;
- [ ] на главной их нет;
- [ ] последний элемент без ссылки;
- [ ] крошки соответствуют пути (раздел → страница).

### B4. Компоненты

- [ ] новости выводятся карточками, дата и картинка на месте;
- [ ] пагинация работает;
- [ ] детальная новость открывается, текст в `.bitrix-content`;
- [ ] события выводятся с датой и категорией;
- [ ] поиск находит новость по слову;
- [ ] подписка отправляет письмо, подтверждение приходит;
- [ ] обращение появляется в `requests`, письмо приходит, в журнале есть запись;
- [ ] бронь появляется в `bookings`, занятый слот не принимается;
- [ ] бронь с e-mail: сотруднику приходит `NLB_NEW_BOOKING`, клиенту —
      `NLB_BOOKING_CLIENT` с датой, временем и услугой;
- [ ] бронь без e-mail (поле пустое): письмо клиенту не отправляется,
      заявка сохраняется;
- [ ] дата в письмах читается как `06.11.2026 (пятница)`, а не `2026-11-06`;
- [ ] администратор в `/personal/` видит карточку «Уведомления о брони»
      и может включить/выключить push (нужен HTTPS и `nlb_push_keys.php`);
- [ ] новая бронь приходит push-уведомлением в браузер сотрудника;
- [ ] без ключей VAPID карточки нет, бронь и письма работают как раньше;
- [ ] заказ появляется в `orders` с товаром, артикулом и количеством;
- [ ] вход/выход работают, кнопка меняется на «Кабинет».

### B5. Производительность

- [ ] главная отдаётся < 1.5 c на локальном стенде (без кеша — < 3 c);
- [ ] после прогрева кеша TTFB < 300 ms;
- [ ] картинки < 300 КБ каждая;
- [ ] нет внешних блокирующих запросов (шрифты системные, CDN нет);
- [ ] `gzip`/`brotli` включены на сервере.

### B6. Безопасность

- [ ] `local/` не отдаёт `.php` как текст;

### F2. Синхронизировать код

`robocopy` **без** `/MIR`: `/MIR` удаляет на приёмнике всё, чего нет
в источнике, — вместе с `bitrix/`, `upload/`, `menu/`, `.htaccess` и
`favicon.ico`, которых в репозитории нет. Рабочая команда:

```powershell
robocopy "D:\nlbbootstrap-main" "D:\bitrix doker\www" /E `
  /XD .git node_modules docs test preview logs `
  /XF *.md *.txt *.bat *.html vercel.json .gitignore ai_extractor.py.py
robocopy "D:\nlbbootstrap-main" "D:\bitrix doker\www" offline.html
```

- `/XD` не копирует то, чего не должно быть в корне сайта: `.git`,
  `node_modules`, `docs/`, `test/`, `preview/` и `db/logs/` (журналы
  миграций пишутся на стенде);
- `/XF` не копирует черновики и служебные файлы корня: `*.md`, `*.txt`,
  `*.bat`, `vercel.json`, `.gitignore`; `*.html` отсекает ручные снимки
  (`II bot.html`, `Smart Site Search Manual.html`, оценки), поэтому
  `offline.html` копируется отдельной командой;
- на стенде остаются нетронутыми `bitrix/`, `upload/`, `menu/`, `.htaccess`,
  `.access.php`, `favicon.ico` и сгенерированный `nlb_push_keys.php`.

Перед первым копированием решить судьбу файлов, которые на стенде новее
репозитория (P1-25 в `../Что доделать.txt`). Сверка sha256 по 108 файлам
поставки даёт шесть расхождений: `urlrewrite.php` (query-string в правилах
detail-страниц), `local/php_interface/init.php` (`Loader::includeModule('iblock')`),
`local/php_interface/include/nlb_forms.php` (имя поля `PROPERTY[NAME][0]`,
`CODE`/`XML_ID` при добавлении), `feedback/index.php`, `services/detail.php` и
`books/detail.php` (`GROUPS => [2]` — иначе гость не может отправить форму).
Копия из репозитория их затрёт и вернёт 404 на `?sent=1` и запрет отправки.

### F3. Миграции, индекс и проверка базы

Все команды — внутри контейнера, из корня сайта:

```powershell
docker exec -w /var/www/html bitrix-web php db/run.php
docker exec -w /var/www/html bitrix-web php tools/build-search-index.php
docker exec -w /var/www/html bitrix-web php db/check.php
```

- `run.php` печатает «Готово: шагов …», «Кеш сайта сброшен» и путь к логу
  в `db/logs/`; повторный запуск безопасен, дубли не создаются;
- `build-search-index.php` пересобирает индекс мгновенной выдачи из живых
  инфоблоков: в репозитории он собран из демо-данных, ID там другие;
- `check.php` должен ответить «OK: структура и демо-контент совпадают
  с db/config». Предупреждения в выводе — повод смотреть `../db/README.md`,
  а не игнорировать.
