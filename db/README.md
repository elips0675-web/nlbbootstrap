# База данных NLB Bootstrap

Набор миграций, который создаёт в 1С-Битрикс структуру данных библиотеки:
типы инфоблоков, шесть инфоблоков, свойства, списки значений, разделы и
демо-контент. Плюс офлайн-линтер и SQL-проверки.

Шаблон `nlb_bootstrap` — только оформление. Без этого каталога страницы
новостей, событий и каталога книг выводить нечего.

---

## 1. Что создаётся

| Инфоблок | Код | Тип | Элементов | Разделов |
|---|---|---|---|---|
| Новости | `news` | `nlb_content` | 10 | 2 |
| События | `events` | `nlb_content` | 6 | 4 |
| Коллекции | `collections` | `nlb_content` | 6 | — |
| Каталог книг | `books` | `nlb_catalog` | 12 | 6 |
| Услуги | `services` | `nlb_services` | 6 | — |
| Печатные услуги | `printing` | `nlb_services` | 8 | — |

Дополнительно: файлы меню `/menu/top.menu.php` и `/menu/bottom.menu.php`
(шаг 006) и, по флагу, привязка шаблона к сайту (шаг 007).

Полное описание полей, свойств и кодов — `docs/db.md`.

---

## 2. Требования

- установленный Битрикс «Управление сайтом» (модуль `iblock`);
- PHP 8.0+ (проверено на 8.3.36);
- доступ к файлам сайта и к базе;
- CLI на сервере (предпочтительно) либо вход администратором в браузере.

Каталог `db/` должен лежать **в корне сайта**, рядом с `bitrix/` и `local/`:
миграции сами вычисляют `DOCUMENT_ROOT` как два уровня выше `db/lib`.

```
<корень сайта>/
├── bitrix/
├── local/
├── menu/            ← появится после шага 006
└── db/              ← этот каталог
```

Если положить иначе — задайте корень переменной окружения `NLB_ROOT`.

---

## 3. Быстрый старт

```bash
# 1. скопировать каталог db/ в корень сайта
# 2. проверить конфиги без базы
php db/lint.php

# 3. создать структуру и контент
php db/run.php

# 4. проверить результат
php db/check.php
```

Ожидаемый вывод `run.php`: 7 шагов, «создано объектов N», «Кеш сайта сброшен».

После запуска:

1. **Настройки → Автокеширование → Очистить весь кеш** (миграции уже
   вызывают `BXClearCache`, но панель надёжнее).
2. **Поиск → Переиндексация** — чтобы поиск нашёл новые материалы.
3. Проверить в админке **Контент → Инфоблоки**: шесть инфоблоков с
   заполненными свойствами.

## 4. Флаги и выборочный запуск

```bash
php db/run.php --only=003          # только свойства
php db/run.php --only=005 --force  # контент (force не влияет на 005)
php db/run.php --force             # перезаписать /menu/*.menu.php
php db/run.php --set-template      # привязать nlb_bootstrap к сайту
php db/run.php --help              # список шагов
```

Шаги:

| № | Файл | Что делает |
|---|---|---|
| 001 | `001_iblock_types.php` | типы `nlb_content`, `nlb_catalog`, `nlb_services` |
| 002 | `002_iblocks.php` | шесть инфоблоков, права на чтение группе 2 |
| 003 | `003_properties.php` | свойства и значения списков (дописывает новые XML_ID) |
| 004 | `004_sections.php` | разделы новостей, событий, книг |
| 005 | `005_elements.php` | демо-элементы с картинками и свойствами |
| 006 | `006_menus.php` | файлы меню в `/menu/` |
| 007 | `007_site_template.php` | привязка шаблона (только с `--set-template`) |

Повторный запуск безопасен: типы ищутся по ID, инфоблоки по `CODE`,
элементы по `XML_ID`. Дубли не создаются, существующие данные не
перетираются (кроме меню с `--force`).

---

## 5. Запуск без CLI (веб-режим)

Если на хостинге нет командной строки:

1. войдите в админку как администратор;
2. откройте `/db/run.php?run=yes`;
3. дождитесь текстового отчёта (может занять минуту);
4. проверка: `/db/check.php`.

Доступ проверяется по `$USER->IsAdmin()`, без входа — 403. После установки
каталог `db/` можно удалить с сервера (но лучше оставить: он нужен для
повторной проверки и отката).

---

## 6. Проверка

| Инструмент | Что проверяет | Нужен Битрикс |
|---|---|---|
| `php db/lint.php` | конфиги, XML_ID, свойства, даты, картинки, иконки спрайта, меню, миграции | нет |
| `php db/check.php` | фактическое состояние базы против конфигов | да |
| `db/sql/checks.sql` | контрольные SELECT'ы для phpMyAdmin | да (только БД) |

`lint.php` включён в общий гейт шаблона (`node tools/check-template.mjs`)
и запускается автоматически, если PHP найден в PATH.

---

## 7. Откат

```bash
php db/rollback.php --yes           # удалить инфоблоки, элементы, разделы, типы
php db/rollback.php --yes --menus   # плюс /menu/*.menu.php
```

Удаляется только своё: элементы и разделы с `XML_ID` на `nlb-`, инфоблоки
из `db/config/iblocks.php`, типы `nlb_*`. Чужие инфоблоки и настройки сайта
не затрагиваются. Перед откатом сделайте резервную копию базы.

Привязка шаблона (шаг 007) откатом не снимается: вернуть прежний шаблон
можно в **Настройки → Сайты → Шаблон сайта**.

---

## 8. Почему не дамп INSERT-ов

Соблазнительно отдать `.sql` с `INSERT INTO b_iblock ...`, но для Битрикса
это небезопасно:

- ID элементов выдаёт таблица `b_iblock_sequence`; прямые вставки её не
  обновляют, и следующий элемент из админки получит занятый ID;
- свойства версии 2 лежат в отдельных таблицах `b_iblock_element_prop_s<ID>`,
  которые создаются при создании инфоблока, а не в дампе;
- часть полей сериализована (`b_iblock.FIELDS`, права, настройки полей);
- кеш и поисковый индекс всё равно нужно перестраивать через ядро.

Поэтому структура создаётся API-миграциями (это и есть «правильный SQL» с
точки зрения Битрикса), а `db/sql/checks.sql` даёт контрольные запросы.
Если нужен переносимый дамп готовой базы — сделайте его после установки:

```bash
mysqldump --single-transaction --default-character-set=utf8mb4 \
  -u root -p biblioteka > biblioteka-nlb.sql
```

## 9. Правка контента

- Тексты и свойства элементов — в `db/config/data/*.php`, затем
  `php db/run.php --only=005` (создаст только новые `XML_ID`).
- Существующие элементы миграция не обновляет: правьте их в админке.
- Новые свойства и разделы — в `db/config/iblocks.php`, затем
  `php db/run.php --only=003,004`.
- После правок: `php db/lint.php` → `php db/run.php` → `php db/check.php`.

Демо-даты (ноябрь 2026) и контакты — заглушки. Перед публикацией замените
их и заполните реальные реквизиты (см. `Что доделать.txt`, P0-9).

---

## 10. Если что-то пошло не так

| Симптом | Причина | Что делать |
|---|---|---|
| `не найдено ядро Битрикса` | `db/` лежит не в корне | переложить или задать `NLB_ROOT` |
| `модуль iblock` не подключён | нет модуля «Информационные блоки» | установить модуль в админке |
| 403 в веб-режиме | нет прав администратора | войти под администратором |
| `каталог /menu недоступен для записи` | права на файлы | создать `/menu/` вручную и дать запись, либо скопировать `db/menu/*.menu.php` руками |
| элемент не создаётся, «раздел не найден» | шаг 004 не выполнен | `php db/run.php --only=004,005` |
| после импорта пусто на сайте | кеш | очистить кеш, проверить `ACTIVE` и даты активности |

Лог каждого запуска — `db/logs/run-YYYYMMDD-HHMMSS.log`. В git/архив его
класть не нужно.
