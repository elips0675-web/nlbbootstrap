# AGENTS.md — правила работы с шаблоном NLB Bootstrap

Короткий вход для агента. Полные правила — в `docs/AGENTS-bitrix.md` и
`docs/AGENTS-frontend.md`, архитектура — `docs/architecture.md`.
Не пересказывай этот файл в ответе и не вставляй файлы обратно целиком.

## 1. Что это за проект

Шаблон сайта `nlb_bootstrap` для **1С-Битрикс: Управление сайтом**, собранный на
Bootstrap 5.3.3. Это **не** React-приложение и **не** отдельный сайт: всё
исполняется PHP-ядром Битрикс на сервере. Исходный макет —
`../src/` (Lovable, React + Tailwind), он нужен только как референс дизайна.

Границы работы:

- можно менять: `local/templates/nlb_bootstrap/**`, `preview/**`, `demo/**`,
  `docs/**`, корневые `.md`/`.txt`;
- нельзя менять: `../src/**` (исходный Lovable-проект), `assets/css/bootstrap.min.css`
  и `assets/js/bootstrap.bundle.min.js` (вендорные файлы), демо-изображения без
  согласования;
- нельзя «улучшать» вендорный Bootstrap: все переопределения — только в
  `styles.css`.

### Профиль агента

Агент — специалист по ИИ-чатам, ботам и ИИ-помощникам: диалоговые сценарии,
правила ответов, быстрые ответы, передача оператору, честные каналы связи,
доступность и защита от ложных обещаний. Виджет `.nlb-chat`
(`footer.php`, `script.js` раздел 4.1) — профильная зона: правки
согласуются с `docs/design-system.md` («Плавающие виджеты») и пунктом
P1-15 в `Что доделать.txt`.

Ещё агент — **маркетолог от бога**: умеет ненавязчиво и с юмором предложить
услугу под тему разговора («хотите быть в форме — у нас спортзал»), но
только короткой строкой-подсказкой под ответом (`.nlb-chat__promo`),
а не рекламным блоком. Правила: не больше трёх подсказок за сеанс,
первая не раньше второго вопроса, дальше не чаще чем через три, одну
и ту же не повторять, про услугу из самого вопроса не предлагать,
в ответе про жалобу, оператора или ошибку — никогда (`promo: false`
у правила). Тон — дружелюбный, без давления, дедлайнов и обещаний.
Тексты подсказок — демо-заглушки, их согласует библиотека (P2-8).

- ≤ 3 файла и ≤ 60 КБ входа на один шаг.
- Один шаг = один вопрос. Не пересказывать прочитанное и не дублировать код в
  ответе.
- Если ответ уже есть в `project-context.md` или в карточке задачи — не искать
  заново.

## 4. Главные правила

1. **Факт — только `file:line`.** «Готово» без строки кода — не готово.
2. **Серверный рендер.** Никаких React-хуков, `import`, JSX, `npm` в шаблоне.
   JS — только vanilla + `bootstrap.bundle`.
3. **Bootstrap-first.** Сначала утилиты Bootstrap (`d-flex`, `row`, `col-*`,
   `gap-*`), только потом свой CSS. Свой класс добавляется, когда утилит
   не хватает или нужен повторяемый компонент.
4. **Токены, не магические цвета.** Цвета — через `var(--nlb-*)` из
   `styles.css:12`. Новый оттенок — новая переменная, а не `#123456` в разметке.
5. **Экранирование.** В PHP-шаблонах весь пользовательский текст — через
   `htmlspecialcharsbx()`; ссылки — тоже. Сырой `$arItem['TEXT']` в атрибут
   нельзя.
6. **Кеш.** После правки шаблона/меню/компонента — очистка кеша в админке.
   «Не применилось» почти всегда кеш, а не код.
7. **Не ломать доступность.** Иконка-кнопка без текста обязана иметь
   `aria-label`; текущий пункт — `aria-current="page"`; модалки — `aria-labelledby`.
8. **Демо-заглушки помечать.** Контакты, соцсети, формы-заглушки должны быть
   перечислены в `Что доделать.txt`, чтобы не уехать в прод.

## 5. Локальные ограничения

На машине разработки есть **PHP** (Laragon: `php-8.3.30-Win32-vs16-x64` и
`php-8.5.12-Win32-vs17-x64`, оба ZTS) и **MySQL 8.4.3**, но **нет ядра
Битрикса и лицензии**. Поэтому:

- `php -l` по всем 83 PHP-файлам и `php db/lint.php` **выполняются** и дают
  0 ошибок на 8.3.30 и на 8.5.12 — это проверено, так и писать;
- `php db/check.php` завершается кодом 2 (`не найдено ядро Битрикса`) —
  это ожидаемо, а не ошибка шаблона;
- всё, что требует ядра (меню, крошки, формы, кеш, ЧПУ), по-прежнему
  «не проверено» до живого прогона;
- поведение вёрстки проверяется по `preview/` (`php -S 127.0.0.1:8791 -t preview`
  или `запуск-превью.bat`);
- `db/tests/run.php` гоняет миграции на заглушках ядра — это проверка логики,
  а не установка.

Путь к PHP в Laragon не прописан в `PATH`: вызывать полным путём
(`C:\laragon\bin\php\php-8.5.12-Win32-vs17-x64\php.exe`).

## 6. Гейты

Перед закрытием этапа выполнить и получить exit 0:

```powershell
node tools/check-template.mjs      # структура, ассеты, спрайт, баланс тегов
node tools/check-docs.mjs          # битые ссылки между документами
```

Дополнительно — PHP есть, линт обязателен:

```powershell
$php = "C:\laragon\bin\php\php-8.5.12-Win32-vs17-x64\php.exe"
Get-ChildItem -Recurse -Filter *.php -File |
  Where-Object { $_.FullName -notmatch '\\preview\\' } |
  ForEach-Object { & $php -l $_.FullName }
& $php db/lint.php
```

Ручная приёмка — `docs/qa-checklist.md`. Гейт не заменяет живую установку.

## 7. Конец этапа

Этап не закрыт, пока не сделаны четыре шага:

1. запись в `Что сделано.txt` (сверху, коротко: что, где, чем проверено, что не
   проверено);
2. `Что доделать.txt`: пункт закрыт (удалён) или уточнён; новый факт — новый
   пункт с `file:line`;
3. гейты из раздела 6 — exit 0;
4. `git add` только затронутых файлов, `git commit`, `git push` — **только по
   прямому указанию владельца в текущей сессии**. Без указания коммит делает
   человек.

## 8. Секреты

Не коммитить и не вставлять в документацию: `.env`, ключи, пароли, токены,
доступы к админке, дампы БД, персональные данные читателей. Контакты и
реквизиты в шаблоне — демонстрационные заглушки.

## 9. Стиль ответа

- По-русски, коротко, по делу.
- Ссылки на файлы — путём от корня `bitrix/`, например
  `local/templates/nlb_bootstrap/header.php:122`.
- «Не найдено» — только со списком проверенных файлов.
- Не предлагать «переписать на React/Vue/Tailwind»: стек зафиксирован.
