1. Резюме

Документация этого проекта сильнее, чем у большинства шаблонов такого размера: есть карта документов, правила, чек-лист приёмки, журнал этапов и бэклог с доказательствами. Проблема не в объёме, а в том, что часть чисел и ссылок отстала от кода — и отстала молча: гейт документации проверяет существование markdown-ссылок и наличие разделов, но не сверяет ни одно число и ни одну ссылку file:line.

Пять выводов

  1. README описывает модель данных трёхдневной давности. README.md:82-85 обещает 6 инфоблоков, 33 свойства и 89 элементов. Факт — 9 инфоблоков, 65 свойств, 91 элемент. Три «лишних» инфоблока — это requests, bookings, orders, то есть персональные данные посетителей. Аудитор, начавший с README, решит, что заявок в модели нет.
  2. README противоречит db/README.md. В одном документе «девять инфоблоков» (db/README.md:4), в другом — «шесть» (README.md:82, docs/installation.md:90), а внутри самого db/README.md — и то и другое (:4 против :84).
  3. Размер фронта занижен в 8,5 раза. docs/security-performance.md:207 и :287 называют script.js размером 8,4 КБ. Факт — 73 595 байт (71,9 КиБ). Там же :283 — «styles.css 47,6 КБ», факт 80 738 байт (78,8 КиБ). Правило docs/AGENTS-frontend.md:127 («CSS не должен расти больше ~50 КБ») нарушено собственным файлом проекта, и об этом нигде не сказано.
  4. Ссылки file:line — самый хрупкий формат. После Stage 44 (мгновенный поиск) header.php вырос на ~20 строк, и таблица «строки → что» в docs/architecture.md:50-60 перестала соответствовать файлу целиком. В docs/bootstrap.md ссылки на script.js уехали на 486–581 строку: аудитор, открывший script.js:900 «Ctrl+K», увидит код распознавания речи.
  5. Главный архитектурный документ не описывает 146 КБ PHP. docs/architecture.md — дерево файлов обрывается на шаблоне: ноль упоминаний local/php_interface/ (9 файлов), local/ajax/ (3 эндпоинта), pwa.js/push.js/consent.js. Формы, поиск, push, фильтр и БД-хелперы живут вне схемы, по которой аудитор судит об устройстве.
Что это значит для приёмки. Числа в документации — не косметика: по ним оценивают объём работ. «6 инфоблоков, 33 свойства» читается как «модель данных маленькая», а «8,4 КБ JS» — как «фронт почти пустой». Обе оценки занижены, причём вторая — на порядок. Пока эти числа не сверяются гейтом, следующая миграция снова сделает документацию неправдой, и заметит это только следующий аудит.

2. Метод и границы

Аудит шёл в два прохода. Сначала — «как читает аудитор»: взять документ, выписать каждое утверждение с числом или ссылкой и предположить, какой вывод из него следует. Потом — «как проверяет разработчик»: для каждого утверждения открыть файл и посчитать.

Что считалось фактом

  • значение, полученное из файла: require конфига, подсчёт строк, размер в байтах, php -l, прогон гейта;
  • строка кода, открытая по указанному адресу и процитированная;
  • вывод самого проекта: php db/lint.php, php tools/filter-selftest.php, php tools/search-selftest.php, php tools/build-search-index.php --check.

Чем проверялось

php db/lint.php                     # 9 инфоблоков, 91 элемент, 12 миграций
php -l по всем *.php вне preview/   # 96 файлов, 0 ошибок
php tools/filter-selftest.php       # 97 из 97
php tools/search-selftest.php       # 109 из 109
php tools/build-search-index.php --check
node tools/check-docs.mjs           # что гейт реально проверяет
node -e "..."                       # require db/config/iblocks.php → 9 / 65 / 0
node -e "..."                       # styles.css, script.js, index.json: байты и строки
node -e "..."                       # сканер ссылок file:line по 31 документу

Размеры приведены в байтах и в КиБ (деление на 1024), потому что документы используют «КБ» без указания базы. Для сравнения с утверждением «8,4 КБ» пересчёт в те же единицы: 73 595 Б = 71,9 КиБ. Разница в 8,5 раза не зависит от выбора базы.

Границы

  • Живое ядро не проверялось — его нет. Всё, что документация утверждает о поведении Битрикса (кеш, права, компоненты), здесь не проверяемо в принципе.
  • Исторические записи не считаются дефектами. CHANGELOG.md:150-151 («6 инфоблоков, 32 свойства, 48 элементов») и старые Stage-записи в Что сделано.txt описывают прошлое состояние — это нормально, пока запись датирована.
  • Числа о происхождении картинок («3722 → 1813 КБ, −51 %») не проверяемы: исходников, которые сжимали, в репозитории нет.
  • Оценки в Оценка дипсик.txt и Оценка qwen.html — предмет отдельного свода (Оценка общее.html), здесь они не пересматриваются.

Правило, которое стоит принять. Ссылка на строку допустима только там, где строка не двигается (например, :root в начале файла) или где она проверяется гейтом. 10. Ограничения аудита

  • Проверялась документация против кода, а не код против требований. Правильный ли BM25, безопасна ли форма брони, работает ли кеш на ядре — это другие аудиты, и без Битрикса они невозможны.
  • Ни одно утверждение о поведении ядра не проверено. Всё, что документы говорят про OnBeforeIBlockElementAdd, кеш компонентов, права групп и электронную почту, остаётся заявлением: подтвердить его можно только на живой установке.
  • Сканер ссылок эвристический. «Смещение» считается по первому вхождению селектора или функции в файл и проверено вручную только для 15 показательных случаев — таблица в разделе 5. По остальным ссылкам утверждение слабее: «строка не пустая».
  • Происхождение изображений не проверяемо. «3722 → 1813 КБ (−51 %)» — единственное число, для которого в репозитории нет исходных данных; оно не включено ни в верные, ни в ошибочные.
  • Срез — 06.11.2026. Любая следующая миграция снова сдвинет числа; именно поэтому предложение в разделе 9 — гейт, а не разовая правка.
