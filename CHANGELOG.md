## [0.5.0] — 06.11.2026

Поиск по сайту: BM25 на PHP вместо Python-сервиса.

### Добавлено

- `local/php_interface/include/nlb_search.php` — токенизация, усечение
  окончаний (падежи, спряжения, возвратность), сборка индекса, Okapi BM25
  (`k1 = 1.5`, `b = 0.75`, idf в варианте Lucene), coord-фактор покрытия,
  сниппет, пофайловые sha256 источников;
- `local/ajax/search.php` — `GET q` (+`limit`), JSON-выдача: `200`, `400`
  (`empty_query`, `query_too_long`), `405`, `503` (`index_unavailable`,
  `search_unavailable`); `Cache-Control: no-store`, `X-Robots-Tag: noindex`,
  запрос не логируется. Контракт вынесен в чистую `nlb_search_api()`
  (`nlb_search.php`) и проверяется самопроверкой, а не только живым запросом;
- `db/search/pages.json` — 8 курируемых страниц (контакты, часы работы,
  запись на событие, афиша, сувениры, каталог, услуги, обратная связь);
- `db/search/index.json` — собранный индекс: 99 документов, 1319 термов,
  средняя длина 39,869 слова, ~331 КБ;
- `tools/build-search-index.php` — сборка индекса и `--check` (свежесть по
  пофайловым sha256, а не по дате файла);
- `tools/search-selftest.php` — самопроверка: индекс и его источники,
  токенизация, математика BM25 на синтетическом индексе, 26 запросов,
  контракт эндпоинта (400/405/503/200) — 109 проверок;
- `db/tests/fixtures/search-cases.json` — 26 запросов с ожидаемым первым
  результатом, присутствием документа или пустой выдачей.

### Изменено

- `header.php`: в модалке поиска появился контейнер `#nlbSearchInstant`
  и `data-search-endpoint` у формы; адрес эндпоинта берётся из атрибута,
  а не собирается из `action`;
- `script.js`: раздел 7 — мгновенная выдача (debounce 250 мс,
  `AbortController`, рендер только через `textContent`, очистка при закрытии
  модалки). Без эндпоинта форма работает как раньше;
- `styles.css`: блок `.search-instant*` (список, заголовок, сниппет);
- `tools/check-template.mjs`: §11.2 — обязательные файлы поиска, вызов
  `nlb_search_query()` в эндпоинте, разметка и стили, свежесть индекса
  по sha256 (гейт краснеет, если данные поправили без пересборки);
- `tools/build-preview-pages.php`: форма поиска в статическом превью ведёт
  на карту сайта, а не на `/feedback/` (раньше «Найти» открывало форму
  обратной связи);
- документация: `README.md` (раздел «Поиск по сайту (BM25)»),
  `project-context.md`, `docs/db.md`, `docs/design-system.md`,
  `docs/AGENTS-frontend.md`, `docs/security-performance.md` (§1.9),
  `docs/qa-checklist.md` (A14, B9), `docs/customization.md` (§12).

### Не проверено

- живой Битрикс: адреса элементов из `DETAIL_PAGE_URL`, права на чтение
  `db/search/` на боевом nginx, поведение на инфоблоках после установки;
- в статическом превью поиска нет — там нет PHP; «Найти» ведёт на карту сайта;
- Python-сервис из `Smart Site Search Manual.html` (VPS) не разворачивался —
  это альтернатива, а не сделанная часть.

## [0.4.0] — 06.11.2026

Фильтр чата на сервере: тот же вердикт, что в браузере.

### Добавлено

- `local/php_interface/include/nlb_text_filter.php` — серверная копия
  `chatProblem()`: мат, оскорбления, реклама, ссылки, бессмыслица;
  тематические корни (`террор`, `насил`, `оружи`, `нарко`, `ненавиж`)
  пропускаются при книжном контексте;
- `local/ajax/chat.php` — `POST message` + `sessid`, ответ JSON (`200` —
  пропущено, `422` — отказ, `400/403/405/413/503` — ошибки запроса);
  текст не логируется и не сохраняется;
- `db/tests/fixtures/filter-cases.json` — общий набор фраз (87) с ожидаемым
  вердиктом для браузера и сервера;
- `tools/filter-selftest.php` — самопроверка PHP-фильтра (exit 0/1);
- `tools/check-filter-parity.mjs` — гейт паритета: списки корней, выражения
  и вердикты `script.js` ↔ `nlb_text_filter.php`.

### Изменено

- `script.js`: блок фильтра обёрнут маркерами `nlb-chat-filter:start/end`,
  гейт паритета отделяет его от остального кода;
- свой домен разрешён и с `www.` (`www.nlb.by`, `www.example.by`): раньше
  после вырезания `nlb.by` оставался `www.` и домен уходил в `spam`;
- проверка бессмыслицы идёт по строке без своих доменов — `www.nlb.by`
  больше не даёт `gibberish` из-за шести согласных подряд в домене;
- `tools/check-template.mjs` требует фильтр, эндпоинт, маркеры и набор фраз;
- документация: `README.md`, `project-context.md`, `docs/design-system.md`,
  `docs/AGENTS-frontend.md`, `docs/security-performance.md`,
  `docs/qa-checklist.md` (A13, B8).

### Не проверено

- живой вызов `local/ajax/chat.php` (нужно ядро Битрикса и `sessid`);
- в браузере эндпоинт не задействован: `USE_REAL_AI = false`, бэкенда
  ответов нет (P1-17 п.1).

## [0.3.0] — 06.11.2026

Бронирование: демо занятости, письма о записи и Web Push.

### Добавлено

- **Web Push** `local/php_interface/include/nlb_push.php` — VAPID JWT (ES256),
  шифрование payload по RFC 8291 (`aes128gcm`), подписки в опции
  `nlb_bootstrap.push_subscriptions`, удаление мёртвых подписок (404/410).
  Без composer и внешних библиотек;
- `local/ajax/push.php` — приём подписки браузера (`subscribe` / `unsubscribe`),
  только для авторизованных, с проверкой `sessid`;
- `assets/js/push.js` — кнопки «Включить / Выключить» и статусы;
- `sw.js` — обработчики `push` и `notificationclick`, кеш `v2`;
- `tools/gen-vapid.php` — генератор ключей VAPID;
- `tools/push-selftest.php` — самопроверка криптографии без сети (20 проверок);
- карточка «Уведомления о брони» в `/personal/` для администратора;
- **письма о брони** — миграция `012_booking_mail.php`: события
  `NLB_NEW_BOOKING` (сотруднику) и `NLB_BOOKING_CLIENT` (клиенту, `#EMAIL#`).

### Изменено

- `nlb_forms.php`: дата в письмах и push — `06.11.2026 (пятница)` вместо ISO;
  бронь больше не уходит общим `NLB_NEW_REQUEST`, а имеет свои события;
- тексты формы брони: подтверждение записи приходит на e-mail;
- `sw.js` кеш-версия поднята до `v2` (новый файл в оболочке).

### Не проверено

- реальная доставка push (нужны HTTPS, живой Битрикс и подписка браузера);
- отправка писем на живом ядре (нужен настроенный SMTP);
- генерация ключей VAPID на боевом хостинге (локально — проверено).

- Lighthouse/PSI на домене, установка PWA на устройствах (нужен HTTPS).

  мобильное меню, автофокус поиска, валидация, Ctrl+K);
- компонентные шаблоны `bitrix:menu` (`top_bootstrap`) и `bitrix:breadcrumb`
  (`bootstrap`);
- `.description.php` — карточка шаблона в админке;
- Bootstrap 5.3.3 локально (`assets/css`, `assets/js`), без CDN и jQuery;
- 16 демо-изображений в `assets/images/`;
- `preview/index.html` — статическое превью без Битрикса;
- `demo/index.php` — демо-лендинг через `header.php`/`footer.php`;
- документация: `README.md`, `AGENTS.md`, `project-context.md`, `docs/*`
  (архитектура, установка, интеграция, Bootstrap, дизайн-система, контент,
  кастомизация, QA, безопасность, roadmap, правила агентов);
- `Что доделать.txt`, `Что сделано.txt`, `Промты.txt`, `CHANGELOG.md`;
- структурные гейты `tools/check-template.mjs` и `tools/check-docs.mjs`.

### Изменено

- дизайн Lovable (React + Tailwind) перенесён на серверный рендер: сетка
  Bootstrap, CSS-переменные вместо utility-классов, vanilla JS вместо React;
- иконки Lucide заменены на inline SVG-спрайт (без внешних зависимостей);
- формы и ссылки переведены на `SITE_DIR` для мультисайта.

### Не проверено

- живая установка в Битрикс (нет PHP/MySQL/Bitrix на машине разработки);
- `php -l` всех файлов;
- работа меню типа `top` и хлебных крошек в ядре;
- отправка форм (`main.feedback`, `subscribe.form`);
- кеш компонентов и страниц.

Подробности — `Что доделать.txt`, раздел P0.

### Известные ограничения

- демо-контакты, соцсети и реквизиты — заглушки;
- формы обратной связи и подписки не подключены к компонентам;
- изображения не оптимизированы (до 599 КБ);
- только светлая тема, только русский язык;
- нет CI, гейты запускаются вручную.
