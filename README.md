# NLB Bootstrap — сайт библиотеки на 1С-Битрикс

Готовый шаблон сайта `nlb_bootstrap` для **1С-Битрикс: Управление сайтом**
(«Старт» и выше): Bootstrap 5.3.3, без сборки, без Node.js на сервере, без jQuery
и без CDN. Внутри — не только шаблон, но и публичные страницы, слой базы данных
(инфоблоки + демо-контент), PWA с баннером установки, уведомление о cookie,
SEO-разметка и заголовки безопасности.

Демо-сайт библиотеки: главная с hero-каруселью, новости, афиша событий, услуги,
каталог печатных услуг, каталог сувениров и мерча, подарочные наборы, контакты,
поиск, личный кабинет.

> **Статус:** всё собирается и проходит офлайн-проверки (`php -l`, `db/lint.php`,
> `db/tests/run.php`, `tools/check-template.mjs`). Живой установки в Битрикс не
> было — ядра и лицензии на машине разработки нет, поэтому всё, что зависит от
> ядра, помечено как «не проверено» (см. [Ограничения](#ограничения)).

## База данных

Миграции — идемпотентные PHP-скрипты на API Битрикса (не SQL-дамп): каждая
сущность ищется по `CODE`/`XML_ID`, поэтому повторный запуск ничего не дублирует.

| Сущность | Сколько |
|---|---|
| Типов инфоблоков | 3 (`nlb_content`, `nlb_catalog`, `nlb_services`) |
| Инфоблоков | 9 (news, events, collections, books, services, printing, requests, bookings, orders) |
| Свойств | 74 |
| Разделов | 12 |
| Элементов демо-контента | 91 |

```bash
php db/lint.php            # проверка конфигов без ядра
php db/check.php           # что реально в базе (нужно ядро)
php db/run.php             # накатить миграции
php db/run.php --only=005  # выборочно
php db/rollback.php        # откат демо-контента
php db/tests/run.php       # автотест на заглушках ядра (65 проверок)
```

Конфигурация — `db/config/iblocks.php` и `db/config/data/*.php`. Даты событий
хранятся в свойстве `DATE` и дублируются в `ACTIVE_FROM`, чтобы афиша
сортировалась и фильтровалась по дате, а не по строке.

## Поиск по сайту (BM25)

`Smart Site Search Manual.html` предлагает Python + rank-bm25 + FastAPI.
Python на shared-хостинге Битрикса нет, а сам BM25 — арифметика без
зависимостей и без сети, поэтому алгоритм перенесён в шаблон на PHP.
Мануальный вариант с отдельным сервисом остаётся в бэклоге для VPS.

| Файл | Роль |
|---|---|
| `local/php_interface/include/nlb_search.php` | токенизация, усечение окончаний, сборка индекса, ранжирование, сниппет, хук обновления и режимы страницы `/search/` |
| `local/ajax/search.php` | JSON-эндпоинт для мгновенной выдачи: `GET q`, `limit` |
| `db/search/pages.json` | курируемые страницы (часы работы, контакты, запись, сувениры) — то, чего нет в инфоблоках |
| `db/search/index.json` | собранный индекс: 99 документов, 1340 термов, ~333 КБ |
| `tools/build-search-index.php` | сборка индекса, `--check` — проверка свежести |
| `tools/search-selftest.php` | самопроверка: индекс, математика, 29 запросов, контракт API, режимы страницы (129 проверок) |
| `db/tests/fixtures/search-cases.json` | ожидаемое поведение запросов |

Формула — Okapi BM25, `k1 = 1.5`, `b = 0.75`, idf в варианте Lucene
(`log(1 + (N - df + 0.5) / (df + 0.5))`), поэтому частые слова не уходят
в минус. Покрытие запроса учитывается coord-фактором (доля найденных слов),
а не жёстким «все слова»: «купить кружку» находит кружку, хотя слова «купить»
в каталоге нет.

```bash
php tools/build-search-index.php          # пересобрать индекс
php tools/build-search-index.php --check  # свежий ли индекс
php tools/search-selftest.php             # 129 проверок
```

Индекс обязан пересобираться после правки `db/config/data/*.php`,
`db/config/iblocks.php` или `db/search/pages.json`: свежесть сверяется по
пофайловым sha256, а не по дате файла (дата врёт после клона). Расхождение
ловит `node tools/check-template.mjs` (§11.2) и `--check`.

После установки индекс обновляется сам: `init.php` подключает библиотеку, а
она подписывает `OnAfterIBlockElement*` на отложенную пересборку в конце
запроса (одна пересборка на все правки). Инфоблоки заявок, броней и заказов
(`index => 'N'`) в индекс не входят. Файлу нужна запись у веб-пользователя
(`db/search/`, в контейнере `www-data`); без неё остаётся ручная команда.

В интерфейсе поиск живёт в модальном окне шапки: пока набирается запрос,
`script.js` ходит в `/local/ajax/search.php` и показывает до пяти ссылок
с заголовком и сниппетом. Это прогрессивное улучшение: без индекса, без PHP
или при 503 список просто не появляется, а форма отправляется в `/search/`
как обычно. Сама страница `/search/` отдаёт BM25-выдачу тем же индексом;
`bitrix:search.page` подключается только как запасной вариант, когда индекса
нет. В статическом превью страница `/search/` собирается без выдачи (форма и
популярные запросы): кнопка «Найти» ведёт на `/search/` живого сайта.

## PWA: установка приложения и офлайн

| Файл | Роль |
|---|---|
| `manifest.webmanifest` | имя, иконки, `start_url`, shortcuts (Каталог, Афиша, Печать) |
| `sw.js` | кеш оболочки, network-first для страниц, `offline.html` при обрыве |
| `offline.html` | автономная заглушка без внешних зависимостей |
| `assets/js/pwa.js` | регистрация SW, `beforeinstallprompt`, инструкция для iOS, «Позже» на 30 дней |
| `assets/js/consent.js` | уведомление о cookie, выбор в `localStorage`, кнопка «Cookie» в подвале |
| `assets/icons/*` | 192/512, maskable, `apple-touch-icon`, favicon, SVG |

Стратегия service worker: CSS/JS/иконки — cache-first, переходы между
страницами — network-first, HTML в кеш не кладётся (на сайте есть авторизация),
запросы в `/bitrix/` не перехватываются.

Баннер «Установить приложение» показывается только там, где установка реально
возможна: Chrome/Edge/Samsung получают `beforeinstallprompt`, Safari на iOS —
инструкцию «Поделиться → На экран “Домой”». Два баннера одновременно не
показываются: второй ждёт выбора по cookie.

> Для service worker и установки нужен **HTTPS** (или `localhost`). На голом
> HTTP баннер не появится — это поведение браузера, а не ошибка шаблона.

### Web Push: уведомления о бронировании

Сотрудник открывает `/personal/` и включает уведомления — браузер сообщает
о новой брони, даже если вкладка закрыта. Клиенту подтверждение записи
приходит письмом.

| Файл | Роль |
|---|---|
| `local/php_interface/include/nlb_push.php` | VAPID JWT (ES256), шифрование payload (RFC 8291, `aes128gcm`), хранение подписок, отправка |
| `local/ajax/push.php` | приём подписки браузера: `subscribe` / `unsubscribe`, только для авторизованных |
| `assets/js/push.js` | кнопки «Включить / Выключить», `PushManager.subscribe`, статусы |
| `sw.js` | обработчики `push` и `notificationclick` (открывает вкладку на нужной странице) |
| `tools/gen-vapid.php` | генерация пары ключей VAPID |
| `tools/push-selftest.php` | самопроверка криптографии без сети (20 проверок) |

Ключи создаются один раз на установку:

```bash
php tools/gen-vapid.php
```

Скрипт пишет `local/php_interface/include/nlb_push_keys.php` (в git не попадает)
и печатает публичный ключ. Альтернатива — переменные окружения
`NLB_VAPID_PUBLIC`, `NLB_VAPID_PRIVATE`, `NLB_VAPID_SUBJECT`.

Без ключей модуль молча выключен: бронь, письма и сайт работают как раньше,
карточка в личном кабинете не показывается. Подписки хранятся в опции
`nlb_bootstrap.push_subscriptions` — отдельной таблицы и миграции схемы нет.
Мёртвые подписки (HTTP 404/410) удаляются при отправке.

> Push требует **HTTPS**: браузеры не выдают `PushManager` на голом HTTP.
> В превью и на Vercel (статические страницы) уведомления не работают —
> проверять на живом Битриксе.

## Безопасность

- **Заголовки** (`local/php_interface/include/nlb_security.php`): `nosniff`,
  `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: strict-origin-when-cross-origin`,
  `Permissions-Policy`, `Cross-Origin-Opener-Policy`, `Cross-Origin-Resource-Policy`,
  HSTS при HTTPS, CSP для публичных страниц (админка исключена).
- **CSP** по умолчанию `default-src 'self'`; отключается строкой
  `define('NLB_CSP', false);` в `local/php_interface/init.php`.
- **`/db/` и `/tools/` закрыты** от веба (`.htaccess` + `robots.txt`): миграции
  запускаются только из консоли.
- **Экранирование**: весь пользовательский и инфоблочный текст выводится через
  `htmlspecialcharsbx()`.
- **Формы**: CAPTCHA, серверная валидация, согласие на обработку данных.
- **Фильтр чата — в двух местах**: браузерный `chatProblem()` (`script.js`)
  и серверный `nlb_text_filter.php` (`local/ajax/chat.php`) дают один и тот же
  вердикт; паритет списков и фраз проверяет
  `node tools/check-filter-parity.mjs`.
- **`robots.txt`**: закрыты `/bitrix/`, `/db/`, `/tools/`, `/search/`, `/auth/`,
  `/personal/` и параметры фильтров.

## Требования

- 1С-Битрикс: Управление сайтом, редакция «Старт» и выше (нужны модули
  `iblock`, `search`, `subscribe`, `main`; они входят во все редакции);
- PHP 8.0+ (синтаксис проверен на 8.3.30 и 8.5.12), MySQL 5.7+/MariaDB 10.3+;
- Apache 2.4 или nginx; для PWA и service worker — HTTPS;
- Node.js **не нужен** на сервере: он требуется только для локальных гейтов
  `tools/*.mjs`.

## Установка

1. Скопируйте содержимое репозитория в `DOCUMENT_ROOT` сайта (там, где лежит
   `bitrix/`).
2. Убедитесь, что каталог `local/` подключён (современные редакции — да).
3. Накатите миграции: `php db/run.php` (создаст типы, инфоблоки, свойства,

4. Привяжите шаблон к сайту: `php db/run.php --only=007 --set-template` или

5. Проверьте `/` — должна открыться главная с контентом из инфоблоков.
6. Очистите кеш: **Настройки → Автокеширование → Очистить весь кеш**.

### Посмотреть дизайн без Битрикса

В `preview/` лежит статическая версия сайта с обычными адресами: `/`,
`/services/`, `/news/`, `/events/`, `/printing/`, `/books/`, `/collections/`,
`/contacts/` и детальные страницы. Она собирается из тех же данных
(`db/config/`), что и Битрикс, поэтому меню, карточки и тексты совпадают.

Проще всего — двойной щелчок по `запуск-превью.bat` в корне репозитория:
он сам найдёт PHP или Python, поднимет сервер на `127.0.0.1:8791` и откроет
браузер. Остановить — Ctrl+C в его окне. Посмотреть, что он нашёл, ничего не
запуская: `запуск-превью.bat check`. Файл сохранён в CP866 — не пересохраняйте
его в UTF-8, иначе русский текст в консоли превратится в мусор.

Вручную:

```bash
# из каталога репозитория (там, где лежит preview/)
php -S 127.0.0.1:8791 -t preview
# открыть http://127.0.0.1:8791/
```

Не открывайте `preview/index.html` двойным щелчком: по `file://` работают не
все ссылки и не регистрируется service worker. Страницы пересобираются
командой `php tools/build-preview-pages.php`.

### Демо дизайна на Vercel

Vercel не исполняет PHP. Если отдать ему репозиторий как есть, по адресу
сайта скачивается `index.php` (`Content-Type: application/x-httpd-php`), а не
открывается страница. Поэтому в деплой едет только статическое демо.

`vercel.json` в корне задаёт сборку: `node tools/vercel-build.mjs` копирует
`preview/` в `public/`, а `outputDirectory: public` раздаёт только этот
каталог. PHP-файлы, `db/`, `local/`, `tools/` и `docs/` в деплой не попадают:
`/index.php` и `/db/config/iblocks.php` на демо отдают 404, а не исходник.

**Внимание:** сборка работает только если `main` назначен production-веткой.
Если проект импортирован не с `main` (или production-указатель остался на
старом деплое), `git push` создаёт **preview**-деплой за логином Vercel, а
корень продолжает отдавать `index.php` файлом. Признак: адрес
`https://<проект>-git-main-<team>.vercel.app/` отвечает `302` на
`vercel.com/sso-api`. Лечится в панели: **Settings → Git → Production Branch**
= `main` → Save, затем **Deployments → ⋯ → Promote to Production**. Подробности
и числа — `Что доделать.txt`, пункт P1-14.

Проверить сборку локально:

```bash
node tools/vercel-build.mjs
# public/: 110 HTML-страниц и ассеты, ни одного .php
```

Пока корень не переключён, демо открывается по адресу `/preview/` —
это тот же снимок `preview/`, просто без заголовков безопасности и без
коротких адресов.

Адреса на демо: `/`, `/news/`, `/events/`, `/services/`, `/services/sauna/`,
`/books/`, `/collections/`, `/printing/` и детальные страницы.

Работает: все статические страницы, меню, карусель, фильтр афиши, картинки
WebP/AVIF, баннер cookie. Не работает и не может работать: формы (нужен PHP),
поиск, вход и регистрация, `/personal/`, подписка, `sitemap.xml`, админка,
PWA-баннер и офлайн-режим (в `preview/` нет `manifest.webmanifest` и `sw.js` —
они лежат в корне шаблона).

Заголовки безопасности из `nlb_security.php` (`X-Content-Type-Options`,
`X-Frame-Options`, `Referrer-Policy`, `Permissions-Policy`, COOP/CORP) заданы
в `vercel.json`, `assets/` кешируется на сутки, старые адреса `/preview/...`
редиректят на корень.

Альтернатива без сборки: **Settings → General → Root Directory** = `preview`
и Redeploy. Тогда `vercel.json` не читается, поэтому не будет ни заголовков,
ни редиректа со старых адресов.

Это витрина дизайна, а не сайт библиотеки. Боевой сайт — PHP-хостинг с ядром
Битрикса и MySQL (раздел «Установка»).

## Проверки

```bash
php -l <файл>                 # синтаксис PHP
php db/lint.php               # конфиги БД без ядра
php db/tests/run.php          # миграции на заглушках ядра
php tools/filter-selftest.php # фильтр чата: 95 фраз, 105 проверок
php tools/search-selftest.php # поиск: индекс, математика, 29 запросов, контракт API
php tools/build-search-index.php --check # индекс не устарел
node tools/check-template.mjs  # структура шаблона + §11.2 поиск
node tools/check-docs.mjs      # ссылки и карта документации
node tools/check-doc-numbers.mjs # числа в документах сверяются с кодом
node tools/check-doc-refs.mjs    # ссылки file:line: файл, строка, якорь рядом
node tools/check-filter-parity.mjs # фильтр чата: браузер ↔ сервер
```

Текущий результат: `php -l` — 0 ошибок (106 файлов вне `preview/`, проверено
на PHP 8.3.30 и 8.5.12), `db/lint.php` — 0 ошибок, `db/tests/run.php` — 65 из 65
проверок пройдено (193 объекта, повторный запуск — 0 новых, книжная база
переводится шагами 009/010), `filter-selftest.php` — 105 из 105,
`search-selftest.php` — 129 из 129, `build-search-index.php --check` — индекс
соответствует источникам, `check-filter-parity.mjs` — 0 расхождений
на 95 фразах, `check-doc-numbers.mjs` — расхождений с кодом нет,
`check-doc-refs.mjs` — мёртвых ссылок нет (сколько проверено, каждый гейт
печатает сам).

Факты для сверки чисел считает `php db/stats.php --json` (типы, инфоблоки,
свойства, элементы, разделы, миграции, PHP-файлы, строки и байты CSS/JS);
документ ничего не доказывает сам себе. Число в тексте разошлось с кодом —
гейт падает с адресом строки, а не ждёт, пока это заметит читатель.

## Ограничения

Помечено как «не проверено», потому что требует живого ядра и домена:

- вывод страниц и компонентов в реальном Битриксе;
- правила ЧПУ из `urlrewrite.php` в админке;
- работа `bitrix:iblock.element.add.form` (запись заявок, CAPTCHA, письмо),
  `subscribe.*`, `search.page`, `system.auth.*`
  (нужны настройки почты, рассылок, индекса поиска);
- CSP и заголовки безопасности на боевом сервере (nginx может переопределять);
- Lighthouse/PSI на живом домене (локально метрики не снимались);
- установка PWA на реальных устройствах (iOS/Android) — нужен HTTPS;
- демо-контакты, соцсети и реквизиты — заглушки, перед публикацией заменить.
