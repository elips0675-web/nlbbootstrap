# NLB Bootstrap — сайт библиотеки на 1С-Битрикс

Готовый шаблон сайта `nlb_bootstrap` для **1С-Битрикс: Управление сайтом**
(«Старт» и выше): Bootstrap 5.3.3, без сборки, без Node.js на сервере, без jQuery
и без CDN. Внутри — не только шаблон, но и публичные страницы, слой базы данных
(инфоблоки + демо-контент), PWA с баннером установки, уведомление о cookie,
SEO-разметка и заголовки безопасности.

Демо-сайт библиотеки: главная с hero-каруселью, новости, афиша событий, услуги,
каталог печатных услуг, каталог книг, коллекции, контакты, поиск, личный кабинет.

> **Статус:** всё собирается и проходит офлайн-проверки (`php -l`, `db/lint.php`,
> `db/tests/run.php`, `tools/check-template.mjs`). Живой установки в Битрикс не
> было — ядра и лицензии на машине разработки нет, поэтому всё, что зависит от
> ядра, помечено как «не проверено» (см. [Ограничения](#ограничения)).

## База данных

Миграции — идемпотентные PHP-скрипты на API Битрикса (не SQL-дамп): каждая
сущность ищется по `CODE`/`XML_ID`, поэтому повторный запуск ничего не дублирует.

| Сущность | Сколько |
|---|---|
| Типов инфоблоков | 3 (`nlb_content`, `nlb_catalog`, `nlb_services`) |
| Инфоблоков | 6 (news, events, collections, books, services, printing) |
| Свойств | 31 |
| Разделов | 12 |
| Элементов демо-контента | 48 |

```bash
php db/lint.php            # проверка конфигов без ядра
php db/check.php           # что реально в базе (нужно ядро)
php db/run.php             # накатить миграции
php db/run.php --only=005  # выборочно
php db/rollback.php        # откат демо-контента
php db/tests/run.php       # автотест на заглушках ядра (17 проверок)
```

Конфигурация — `db/config/iblocks.php` и `db/config/data/*.php`. Даты событий
хранятся в свойстве `DATE` и дублируются в `ACTIVE_FROM`, чтобы афиша
сортировалась и фильтровалась по дате, а не по строке.

## PWA: установка приложения и офлайн

| Файл | Роль |
|---|---|
| `manifest.webmanifest` | имя, иконки, `start_url`, shortcuts (Каталог, Афиша, Печать) |
| `sw.js` | кеш оболочки, network-first для страниц, `offline.html` при обрыве |
| `offline.html` | автономная заглушка без внешних зависимостей |
| `assets/js/pwa.js` | регистрация SW, `beforeinstallprompt`, инструкция для iOS, «Позже» на 30 дней |
| `assets/js/consent.js` | уведомление о cookie, выбор в `localStorage`, кнопка «Cookie» в подвале |
| `assets/icons/*` | 192/512, maskable, `apple-touch-icon`, favicon, SVG |

Стратегия service worker: CSS/JS/иконки — cache-first, переходы между
страницами — network-first, HTML в кеш не кладётся (на сайте есть авторизация),
запросы в `/bitrix/` не перехватываются.

Баннер «Установить приложение» показывается только там, где установка реально
возможна: Chrome/Edge/Samsung получают `beforeinstallprompt`, Safari на iOS —
инструкцию «Поделиться → На экран “Домой”». Два баннера одновременно не
показываются: второй ждёт выбора по cookie.

> Для service worker и установки нужен **HTTPS** (или `localhost`). На голом
> HTTP баннер не появится — это поведение браузера, а не ошибка шаблона.

## Безопасность

- **Заголовки** (`local/php_interface/include/nlb_security.php`): `nosniff`,
  `X-Frame-Options: SAMEORIGIN`, `Referrer-Policy: strict-origin-when-cross-origin`,
  `Permissions-Policy`, `Cross-Origin-Opener-Policy`, `Cross-Origin-Resource-Policy`,
  HSTS при HTTPS, CSP для публичных страниц (админка исключена).
- **CSP** по умолчанию `default-src 'self'`; отключается строкой
  `define('NLB_CSP', false);` в `local/php_interface/init.php`.
- **`/db/` и `/tools/` закрыты** от веба (`.htaccess` + `robots.txt`): миграции
  запускаются только из консоли.
- **Экранирование**: весь пользовательский и инфоблочный текст выводится через
  `htmlspecialcharsbx()`.
- **Формы**: CAPTCHA, серверная валидация, согласие на обработку данных.
- **`robots.txt`**: закрыты `/bitrix/`, `/db/`, `/tools/`, `/search/`, `/auth/`,
  `/personal/` и параметры фильтров.

## Требования

- 1С-Битрикс: Управление сайтом, редакция «Старт» и выше (нужны модули
  `iblock`, `search`, `subscribe`, `main`; они входят во все редакции);
- PHP 8.0+ (проверялось на 8.3), MySQL 5.7+/MariaDB 10.3+;
- Apache 2.4 или nginx; для PWA и service worker — HTTPS;
- Node.js **не нужен** на сервере: он требуется только для локальных гейтов
  `tools/*.mjs`.

```bash
# 1. Скопировать содержимое репозитория в DOCUMENT_ROOT сайта

# 3. Создать инфоблоки, меню и демо-контент

# 4. Привязать шаблон к сайту
php db/run.php --only=007 --set-template
```

Без Битрикса дизайн смотрится в `preview/index.html` (открывается двойным
щелчком). Подробная установка — ниже.

## Установка

1. Скопируйте содержимое репозитория в `DOCUMENT_ROOT` сайта (там, где лежит
   `bitrix/`).
2. Убедитесь, что каталог `local/` подключён (современные редакции — да).
3. Накатите миграции: `php db/run.php` (создаст типы, инфоблоки, свойства,
   разделы, меню и демо-контент).
4. Привяжите шаблон к сайту: `php db/run.php --only=007 --set-template` или
   вручную: **Настройки → Настройки продукта → Сайты → Список сайтов → Шаблон**.
5. Проверьте `/` — должна открыться главная с контентом из инфоблоков.
6. Очистите кеш: **Настройки → Автокеширование → Очистить весь кеш**.

Подробнее — `docs/installation.md` и `docs/bitrix-integration.md`.

## Ограничения

Помечено как «не проверено», потому что требует живого ядра и домена:

- вывод страниц и компонентов в реальном Битриксе;
- правила ЧПУ из `urlrewrite.php` в админке;
- работа `bitrix:main.feedback`, `subscribe.*`, `search.page`, `system.auth.*`
  (нужны настройки почты, рассылок, индекса поиска);
- CSP и заголовки безопасности на боевом сервере (nginx может переопределять);
- Lighthouse/PSI на живом домене (локально метрики не снимались);
- установка PWA на реальных устройствах (iOS/Android) — нужен HTTPS;
- демо-контакты, соцсети и реквизиты — заглушки, перед публикацией заменить.
